# 检索架构

检索将当前项目树转为一份有界、可检查的证据。每次请求读取当前 Markdown 与源码，共享一个截止时间，明确报告部分结果；不依赖向量数据库或长期索引。

```text
自由文本请求
    ↓
query.py       意图、证据需求、工作区范围
    ↓
index.py       阶段编排与稳定索引模式
    ├─ stages/discovery.py   安全发现文件，不跟随符号链接
    ├─ stages/selection.py   渐进遍历路由，限制 I/O
    ├─ stages/documents.py   Markdown 语义、来源与逻辑条目范围
    ├─ stages/lexical.py     多语言分词与 BM25 统计
    └─ stages/ranking.py     结构与词法的倒数排名融合
    ↓
routing.py     基于证据推断领域与模块
    ↓
pipeline.py    知识正文、当前源码与约束
    ↓
delivery.py    公平采集、覆盖统计与上下文预算
```

`runtime.py` 与 `stages/sections.py` 是薄兼容入口。新代码依赖职责所属模块的公开函数与结果对象；兼容入口保护早期集成，不承载新业务。

## 设计不变量

- Markdown 索引只活在当前请求中，持久化旧索引不能冒充当前知识。
- `RetrievalBudget` 贯穿路由、回退与交付，可选工作不能重置时钟。
- 先分别排序标题，再按逻辑条目范围合并，让条件、失败分支与恢复说明共同交付。
- 正文与规则池使用同一条目身份和范围；不同命中小节不重复占额，长条目与源码摘录保留截断标记和准确续读目标。
- 命中的正文导航链接仅单跳展开至已发现的知识文件，片段提供定向排名信号；不递归遍历、不改变规则权威，沿用同一时间与字节预算。
- 覆盖统计只回答是否检索到所需证据类型，不证明事实正确、完整或已获批准。
- 不安全文件、无效元数据、字节限制与超时形成结构化问题，可与可用结果一起返回。
- 路径顺序、摘要、同分决策与排名融合保持确定性。
- 摘要、来源、锚点、候选和最终上下文都有明确上限与后续读取目标。

新检索信号属于 `stages/ranking.py`，新证据源属于 `pipeline.py`，交付策略属于 `delivery.py`。外部映射键保持既有 camelCase，Python 标识使用 snake_case。可恢复的阶段返回诊断与部分结果；无效调用契约或无法解释的状态才抛异常。

Module 与专题的源码锚点按问题和命中条目优先读取，声明核验与 sync、verify 共用 `source_anchors.py`，单请求内复用当前文件的解析。未填写 `endLine` 时读取当前声明范围；唯一行号漂移可定位到当前声明，同时保留文件头待维护的缺口。注释、调用和其他所有者的同名符号不能冒充有效锚点；歧义或解析不可用时返回缺口与有界搜索线索。锚点是文档级关联，不能证明某个小节的语义或行为完整。

变更意图或显式 `purpose=change` 增补 `domain-knowledge` 与 `engineering-constraint` 两类覆盖提示，分别表示业务正文与工程约束到场。旧 `business-rule` 保留兼容语义；新提示仍是 `retrieval-hint-only`，缺失不构成任务门禁。实现适用性、C4 决定及 C5 验收由 [using-modus](../scaffold/templates/skills/using-modus/SKILL.md) 和助手拥有。
