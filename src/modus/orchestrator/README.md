# 应用编排层

本包协调证据提供方，不拥有检索算法、终端展示或知识写入。源码与知识的组合必须有明确范围、统一预算和可解释的降级结果。

```text
CLI / 助手适配器
    ├── preflight          安装与知识可用性观察
    ├── context_resolver   一个请求、一个预算、一份证据结果
    └── knowledge_sync     源码变化 → 待评审知识
              │
    契约与策略：models / path_scope / query_terms / search_policy
              │
       检索与文件系统
```

## 设计不变量

1. 未初始化或缺少知识时，当前源码仍可使用，不增加接入门槛。
2. 知识正文引导导航，实现结论以当前源码核验。
3. 上下文解析向各可选阶段传递同一个截止时间与输出预算。
4. 无效路径与过时归属前缀不能把搜索范围扩展到全仓。
5. 搜索结果有界，常见敏感值在越过编排边界前脱敏。
6. 检索或 `rg` 失败形成结构化状态；可回退时回退，不暗中改变请求含义。
7. `knowledge_sync` 只提出评审候选；哈希条件写入属于包外职责。

影响检查扫描当前规范知识文档，包括 Module、专题及分片，通过 `anchors.locations` 和 `anchors.paths` 匹配变更路径；人工文件即使命中也不会获得写入授权。声明核验与检索、verify 共用 `source_anchors.py`，行号漂移、符号缺失、歧义和不可核验位置进入评审线索。文件改名时调用者应提供本轮旧、新路径；候选为空仍需由助手追查入口和消费者，不能当作无影响结论。

## 模块地图

| 模块 | 责任 |
| --- | --- |
| `context_resolver.py` | 验证与组装公开上下文协议 |
| `preflight.py` | 观察安装与已创作知识的可用性 |
| `knowledge_sync.py` | 将源码变化关联到知识锚点 |
| `module_meta.py` | 读取与实际位置绑定的模块元数据，明确降级 |
| `fallback.py` | 已有搜索消费者的兼容入口 |
| `evidence_search.py` | 执行 ripgrep 或无外部依赖的 Python 搜索 |
| `query_terms.py` | 提取有优先级的多语言检索信号 |
| `search_policy.py` | 统一遍历、范围与脱敏规则 |
| `path_scope.py` | 规范化并约束用户指定的项目路径 |
| `models.py` | 内部值对象与 JSON 边界类型 |

新增证据后端应在 `evidence_search.py` 实现执行，并复用 `search_policy.py`，不复制文件系统或脱敏策略。新增编排服务应把协议组装放在边界，以类型模型表达稳定概念。本包启用严格 mypy；公开字典结构或兼容入口变化需有契约测试。
