# 共享检索与降级

## 路由

先复用用户请求、显式路径、对话材料和已经核实的证据。已知源码路径、
接口、符号或知识文件时直达；范围未知时沿以下导航定位：

1. 读 `modus/knowledge/architecture-overview.md` 选择相关 Domain。
2. 读 Domain `SKILL.md` 选择 Module 与专题。
3. 定位相关 Module、rule/api/object/state_machine 等正文及源码入口。

优先找当前场景的主定义与适用规范，不把同一事实的多处复述当作相互
独立的证据。人工业务材料只在相关时读取，具体核验见下文[证据读取与核验](#证据读取与核验)。

### 业务与工程联合定位

`modus/knowledge/domain/` 补充业务对象、场景、条件、完成与恢复；
`modus/knowledge/constraint/` 补充工程边界、现有能力和有条件的默认
写法。两者不是互斥分类：业务不变量也约束实现，工程规范也提供实现
知识。普通业务解释通常以 domain 为主；涉及实现选择、技术方案、代码
示例或工程评审时才联合读取适用 constraint，不全量加载两个目录。

从命中的业务场景联读相关规则、状态和契约。工程约束先沿 Team Standard
场景导航与适用路径/环境，再按稳定条目锚点读取复用入口、默认写法、
示例前提与例外。小项目可在入口内完成，复杂项目按需进入
`constraint/team-standard/<topic>.md`。

业务描述与工程术语不一定相同，先理解实际行为，再补充工程问题：同一
操作可重放时查幂等与副作用；批量任务查部分成功、顺序与资源上限；
公开字段变化查兼容、序列化及消费者。没有场景依据时不机械扩展关键词。
反向也要核对：工程方案采用并发、事务或共享执行器时，回查业务是否允许
乱序、部分提交、取消或重做。两类知识保留各自主定义，通过现有链接关联，
不复制成第三套规则库。

### 证据读取与核验

围绕当前决定读完整逻辑条目，保留祖先标题、所属接口/对象/场景、来源
性质、前提、例外、失败与恢复。规则名称不能代替正文，示例需连同依赖
与平台条件读取；截断时沿准确标题、条目或源码坐标续读。

深度由本次问题和变化决定：改判断条件核对分支两侧的可见结果；改状态
核对进入、终结与恢复；改契约核对提供方和实际消费者；改共享能力核对
真实签名、版本、装配与资源所有权。这不是每次必读的文件清单。

声称当前实现行为、诊断原因或准备修改关键行为时，回到相关源码、配置、
测试和实际差异核验。知识问答可以依据明确材料回答其所述内容，无需自动
扩展成全仓源码调查，也不能据此宣称已经验证运行时现状。事实与要求的
性质及冲突按[约束使用说明](constraint-usage.md#区分性质与证据)处理；
是否继续补证按 [C3](consumption.md#c3-证据收敛) 判断。

已知位置缺少条件时先续读；未命中时区分范围、导航、内容或预算问题，
按缺口补查，不统一放大 top-k 或重扫全库。

## 普通工作流边界

`using-modus`、context、hooks、update/sync 和公开 status 都不
导入、不读取、不构建 `modus/.cache/init-analysis/`。即使缓存存在也
一样。调用链、影响面、资源效应和拓扑问题通过正文定位后直接核验源码。

只有 `/modus-init` 与 `/modus-reinit` 按统一生命周期同步构建并消费
本轮显式 bundle。不存在公开 graph query 或 refresh 路径。

## 降级

| 状态 | 行为 |
| --- | --- |
| 有正文且可读 | 按[证据读取与核验](#证据读取与核验)渐进取证 |
| 正文缺失或损坏 | 直接检索当前源码和用户材料 |
| CLI 不可用 | 使用宿主的文件读取和搜索能力 |
| 证据冲突 | 按[继承、冲突与应用](constraint-usage.md#继承冲突与应用)区分事实与要求，解决会影响结果的分歧 |
| 关键材料不可读 | 说明影响，不推测其内容 |

缺少 Modus 安装、缓存或索引不阻止普通任务。不要为了“准备环境”创建
模板、运行初始化分析或修改正文。

## 便利接口

助手直接读文件与调用 `modus context resolve "问题" --scope project-read`
遵守同一协议，按当前定位需求选择，CLI 不是必经步骤。明确用于实现
变更时传 `--purpose change`，即使问题同时包含错误、接口或依赖等词；
这只补充取证需求，不授予修改权限。续查时传具体问题、purpose 和已知 `--path`。

CLI 按当前正文定位，命中的导航行或条目链接可单跳展开到已发现的知识
文件及片段，保留同一请求预算，不递归扫描链接树。已知源码路径也可
通过正文中的结构化锚点定位所属知识；该关联仍需回当前源码核验。
无匹配、预算受限或链接片段失效时，结合缺口与原文继续定向读取。

消费结果时分清三个层次：

- `evidence`、`applicableConstraints` 与 `constraintCandidates` 是材料及适用性线索，不代表规则已获批准或已正确应用。链接、排名与范围也只帮助定位；规则池与正文池都按完整逻辑条目交付，未命中项目规范仅作候选。
- 变更请求的 `coverage` 分别提示 `domain-knowledge`（业务正文）和 `engineering-constraint`（工程约束）是否到场；旧 `business-rule` 保留宽泛的兼容语义。来源类别不能证明材料完整、正确、适用或要求已落实，缺失也不是任务完成门禁。
- `truncated` 与 `continuation.readTargets` 指向需要续读的条目或源码范围。源码搜索摘录只是定位窗口，锚点可达也不证明行为完整；只补当前决定需要的内容，不遍历全部候选。

返回结果不含初始化分析的机器层 freshness；普通消费不因此构建或
刷新分析。后续是否继续取证或执行，按[阶段衔接与停止条件](consumption.md)判断。
