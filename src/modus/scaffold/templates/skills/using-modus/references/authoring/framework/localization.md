# 正文语言与本地化

正文默认使用简体中文，覆盖标题、解释、导航、表格与图表标签。只有用户明确指定其他语言时才切换；不根据源码注释、输入材料或会话语言自动切换。

一个知识树保持主要语言一致。reinit 遇到历史外语正文时，在本次已确认范围内统一为目标语言；局部更新只修订授权范围，保留无关文档与人工维护内容。混合材料先归一语义，再用目标语言表达。

段落顺序、步骤、表格、贯穿案例与图前图后说明统一遵循[正文编辑与阅读排版](editorial.md)。本文件只拥有语言、术语和精确标识规则，不另设一套排版或篇幅要求。

文件路径、Domain/Module slug、源码标识、协议名、配置键、枚举传输值和命令在精确引用、字段定义及可执行内容中保持原样；这一要求不意味着自然叙述也只写代码标识。自然标题、解释和读者导航使用目标语言；已有适用的目标语言定义直接采用，不逐字硬译，也不为了匹配预设改写仍然清晰的已有标题。

创作开始时依据用户明确要求或默认值确定本轮目标语言，并将同一要求传给取证后的正文创作、图表、协作者与回读；不新增语言配置文件或确认步骤。原材料中的释义先核对含义再用目标语言表达，不能把翻译当成项目实际显示值。

## 术语解释、行为表达与来源追溯

正文应让目标读者理解谁在什么条件下做什么、得到什么结果。以下规则适用于所有运行形态与正文语言，覆盖后端、前端、任务、命令行和类库；不要求所有专业术语都翻译成中文。

| 通用规则 | 写作要求 |
| --- | --- |
| 优先使用有证据的业务名称 | 业务缩写、内部代号、历史名称、状态码和枚举值，先核对项目注释、定义或文档中的含义及适用范围，再采用读者能理解的业务或能力名称。不能凭拼写、相似词或通用缩写表猜测项目含义。 |
| 区分自然叙述与精确标识 | 叙述、标题和图表标签使用已证实的业务名称；接口、字段、配置、命令和代码示例中的精确标识保留原始拼写。已有目标语言释义的状态或枚举，在可独立阅读的页面或场景首次出现时写“目标语言含义（`原始码`）”，后续叙述优先用该名称；需要比对精确值时保留原码。不能为了表达通顺改写可执行内容或协议值。 |
| 解释行为，不只转述代码 | 方法说明用途、触发与结果；布尔值说明控制什么，以及影响行为的真/假分支和默认值；状态说明进入、退出条件及责任；返回值说明代表受理、局部提交还是最终完成。根据实际机制说明后续完成信号，不能把方法名、`true` 或成功码直接当作完成证明。 |
| 保留条件、例外与不确定性 | 简化表述仍须保留影响行为的前置条件、分支、顺序、例外和恢复边界。未找到可靠含义时保留原词并说明尚未证实的部分；同名异义按领域、模块或版本区分；材料冲突时说明差异，区分当前行为与文档意图。 |
| 来源放入现有元数据 | 支撑解释的代表性文件记录到已有 frontmatter `anchors.paths`，准确源码位置记录到 `anchors.locations`，同一来源复用。正文连贯说明含义与行为，不堆砌源码坐标或证据清单；不虚构位置、符号或另造术语元数据字段。 |

`qm`、`kg`、`kw` 只是待解释标识的示例，不预设其业务含义，也不建立专用替换规则。项目已有清晰的专业术语可保留原文，必要时解释它在当前场景中的作用。取证与冲突处理遵循[场景闭合](../evidence/scenario-closure.md)，成稿按[通用可读性问题](../publication.md#通用可读性问题)回读。

### 已定义中文含义的应用

本节的中文名称、中文标签和中文说明要求仅在目标语言为简体中文时适用。其他目标语言仍核对相同的类型、字段和释义来源，再以目标语言表达；精确显示值和原始引用保持原文，必要时附目标语言解释。

先区分符号身份、实际传输/存储值和中文显示名。枚举成员名不一定等于 `code`，`value` 也不一定是显示文案；须读取定义、构造参数与字段绑定，以及相关 getter、序列化或显示转换。中文含义可来自当前枚举的显示字段、明确注释、实际字典/国际化映射或适用的业务材料。依据按同一业务对象、类型、字段及版本绑定，不能把一个同名代码的释义套到其他状态系统。

已有中文名称且与当前使用语义一致时，必须采用该名称；不能只把映射留在 Object 字典，其他正文继续仅使用英文原码。保留原文的专业术语不包括这类已有明确中文含义的业务状态。同一概念的材料、解释性注释、模块、专题、案例和图中标签沿用同一名称；只处理本轮生成或获授权维护的内容，不自动改写业务源码、历史注释或无关材料。

| 使用位置 | 表达要求 |
| --- | --- |
| 业务段落、步骤、规则、案例 | 中文为主；当前页或独立场景首次使用时附原码，关键条件仍可写中文加原码以便核对 |
| 对象字典、枚举对照 | 精确列出成员/传输值与中文名称；补充行为、适用范围和例外，不能只有代码列表 |
| 图中可见名称和说明 | 使用中文标签；内部节点 ID 可以保留原符号，必要时在标签或图注附原码 |
| 请求/响应 JSON、SQL 条件、命令、程序比较表达式 | 保留真实字段和协议值；中文含义写在相邻解释或适用语言的注释中，不改载荷 |
| 本轮新写的说明性注释或引用原始日志 | 新写注释优先使用已定义中文；原始日志/原文引用保留准确内容，在旁边解释，不篡改引用 |

未找到定义时定向查相关声明和映射；机器包只给出符号或未附释义，不代表源码没有中文。仍不可得时保留原词并明确含义未确认，不自行翻译后当作项目定义。注释、材料与当前实现不一致时说明各自范围和差异；显示名只证明名称，状态推进与完成含义仍以行为证据核验。不得全局字符串替换或建立脱离类型/字段的翻译词表。

成稿时从已核验的映射反查当前范围内的使用位置：若字段字典有中文，模块段落、条件表或图仍仅出现原码，就按内容缺陷修复。把原码加反引号只能标明技术身份，不能代替中文解释。取证和回读复用既有场景记录、唯一主定义与 frontmatter，不新增术语 schema 或独立账本。

## 标题表达起点

| 产物 | 简体中文起点 | 用户明确要求英文时 |
| --- | --- | --- |
| 根概览 | 项目总览；系统架构；能力地图；知识导航；开发与排障 | Project overview; System architecture; Capability map; Knowledge navigation; Development and troubleshooting |
| Domain | 领域定位；结果与边界；专题导航；模块全景 | Domain positioning; Outcomes and boundaries; Topic navigation; Module landscape |
| Module | 模块定位与边界；核心场景与行为；实现、扩展与验证 | Module scope; Core scenarios and behavior; Implementation, extension and verification |
| 专题 | 总览；按真实事实命名的详情 | Overview; Details named after real facts |

这些是表达起点，不是验证器要求。导航层标题可以稳定；场景 H3 应由真实任务自然命名。只有路径、身份和机器字段属于硬协议。
