# 按 Domain 并行撰写

未获委派授权时由同一作者执行。只有用户明确授权委派、宿主具备能力、Scope 已确认、原执行卡已建立，且至少两个完整 Domain 的正文所有权可隔离时，才启用本协议。执行方式的取舍见[范围确认](evidence/scope-modeling.md#对话中的确认输出)，两种方式的质量要求相同。

## 所有权

- 一个 Domain 任一时刻只有一个正文作者，完整负责六专题、所有 Module、Domain 路由、案例、图表及域内验收；不按文件类型/Module 拆给多个作者，worker 不继续委派。
- 根作者独占用户/Scope 决策、唯一执行卡、根概览、Team Standard、business seed、跨域事实裁决与最终 publication。
- worker 只写所分配域的生成正文，人工 business、其他域、共享目标、源码与 Git 均禁止写入。
- 依赖和循环关系先按[跨域合同](cross-domain.md)消歧；selector 重叠或事实所有权有争议时先处理边界，不能仅凭目录不同并发定稿。

## 派发前建立共同输入

K2 先准备跨域协作基线和各域事实输入包。每个 worker 使用同一份[固定委托合同](domain-worker-prompt.md)及 K2/K3/K4 入口；根作者只填事实参数，不逐域自由改写指令。把输入包、合同定位和实际发送文本保存到原卡正文，用户可查看，后续作者可复核。

输入必须包含全部 Module/selector、证据双摘要、当前阶段/进度、精确可写/保护路径、读时哈希、用户质量要求、材料与主定义、跨域基线、目标页/案例/图形与待验位置。worker 先实际读原卡，再按[恢复合同](context-continuity.md)读取本域证据、相关正文和完整规范；任务消息不能代替这些读取。

## 按依赖分波

保留根作者的审阅能力和一个可用槽位，根据宿主能力调度。先稳定提供方的共享契约，再派发依赖它的正文；循环关系先联合取证。不要让同一 worker 连续吞下多个 Domain，新的完整域使用独立输入包和上下文。

首波在依赖允许时选择一个复杂域和一个普通或证据较薄的域。根作者读取实际文件和回读结果后，修正共同输入或返修；首波通过前不批量派发剩余域。不能用首波质量承诺后续质量，每个域仍完成相同验收。

worker 完成可恢复单元后发送增量进度和所用协作基线，继续本域下一单元；根作者及时合并到原卡，不设置逐单元等待确认。只在所有权/共享事实冲突影响后续工作，或即将压缩、退出、换作者而进度尚未保存时等待根作者处理。宿主仅能在 worker 结束时交回结果的，按可恢复批次交接，根作者保存后立即安排同域续作；一次 handoff 不等于整域完成。

共享基线变化时，根作者通知受影响作者定向重读、重验；无依赖单元继续，不让旧基线成果进入最终 reviewed。

## 验收与收尾

worker 按 K4 完成本域源码 coverage、全部目标的逐篇回读、实际预览与 verify，并按固定合同交接。根作者读取实际文件，至少覆盖 Domain 路由、六专题、简单/普通/最复杂的代表性 Module，核对清单与全文回读记录、场景深度、案例/图形、来源、完成/恢复和跨域交接。

根作者抽查只是二次校准，不能替代 worker 的全量逐篇验收；worker 结束或 verify clean 均不等于 reviewed。逐条核对该域全部跨域输入/输出与最新基线，受影响事实未修复、遗漏条目或已知阅读缺陷未解决时定向返修。根作者串行更新既有状态；未运行预览单独保留待验位置，不记视觉通过。

所有域达到语义 reviewed 后，根作者串行执行 K5/K6。按[发布合同](publication.md)完成 publication、发布后回读和整页/逐图验收后才清卡；视觉待验项不能因 worker 结束而删除。

## 中断与冲突

worker 超时或失败时，根作者先读原卡，再核对实际 diff、未知写入与 handoff，保存已核实进度。优先由原作者定向续作；必须换作者时先确认前任已停止写入，再交付同一固定合同、完整输入与最新基线，不能两人同时覆盖。

恢复按[上下文合同](context-continuity.md)先读卡定位，再补实际缺失输入；仍完整有效的内容复用。不重跑 build、重做 Scope 或从文件数量猜进度。CAS 冲突只影响相关文件/Domain，不刷新哈希后盲目覆盖，其他无依赖域继续。原卡缺失不得从输出拼装缩小的全 reviewed 卡。
