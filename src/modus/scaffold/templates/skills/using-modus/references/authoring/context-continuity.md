# 上下文保存与恢复

init/reinit 的串行作者与已授权 Domain worker 共用本合同。唯一持久执行依据是原 `modus/.cache/knowledge-authoring/scope-confirmation.md`，schema 与状态见[范围合同](evidence/scope-modeling.md)。检查点保存在原卡正文，不新增卡片、状态机或回执。

## 压缩前保存什么

每完成一个契约组、对象或完整场景，根作者原位更新检查点；worker 通过 handoff 返回事实，确认根作者已保存后继续。不要等待压缩提示。下一单元无法同时容纳取证、成文与回读，或已不能准确复述关键条件时，先保存，再缩小工作单元；完整范围和解释深度保持不变。

| 保留项 | 恢复所需内容 |
| --- | --- |
| 身份与授权 | 工作流、仓库/成员、完整确认范围、排除项、质量要求、委派授权、保护路径 |
| 执行位置 | 当前 K 阶段、Domain/Module、页面及接口/字段/场景条目、最近完成的检查、最早未完成动作 |
| 证据会话 | build 的实际结果、双摘要或不可用原因、Module ID → 请求/packet requestedScope、已读记录/源码、已核验事实与正文落点、缺口/省略处置 |
| 覆盖与判断 | 全部目标及未完成项；实现、要求、示例、待确认项的区别；关键条件、否定项、例外和依据 |
| 跨域边界 | 已接受的协作基线、主定义所有者、输入输出/状态映射、完成与恢复责任、消费者及未决冲突 |
| 规范与系统 | Team Standard 状态、授权和读时哈希；机制/使用者/反例到规则条目的映射；K4/K5 最终版本、K6 概览引用及待核对交接 |
| 文件版本 | 写前 CAS 哈希、最近验收版本、已写未验位置、结果未知的写入及并发变化 |
| 验收债务 | 待补证事实、未预览章节、待渲染 visual id、阅读缺陷及下一动作 |

原卡正文只保留一个“当前检查点”，包含当前阶段、工作单元和最早未完成动作；新进展原位替换该段，完整范围、事实对账和验收债务保留在原有各部分，避免历史指令与当前动作竞争。长清单按 Domain、对象或契约组组织，原位维护当前有效记录，不追加重复历史日志。准确事实可压成带来源的短记录；不得删去后续域、未决项或交接关系来缩短卡片。计划暂停或交接前按同一要求保存。

## 宿主摘要与上下文容量

能定制摘要时，保留原卡实际路径、本轮身份与授权边界、当前阶段/条目、最早未完成动作、已尝试构建、协作基线和验收债务；明细指向原卡位置，并注明“恢复先实际读卡，不能凭摘要续写”。不能只记已完成文件数或最后一个域。

不能定制摘要或主动刷新时，以持续保存原卡和下述重载流程兜底；不假定宿主会保留关键事实。恢复不要求新建聊天、启用 subagent 或再次确认已有授权。

## 逐域加载与恢复

首次进入 Domain，或压缩、会话恢复、作者交接后无法完整持有本域范围、证据、正文和适用规范时，按以下顺序加载。除定位卡片外，**第一项恢复工作必须是实际读卡**；摘要、任务消息和服务端“之前发送过”只用于定位，不能证明当前作者仍持有内容。

同一作者切换或返回已调查的 Domain、工具失败或取消后重试时，先判断当前上下文是否仍完整持有相关内容，以及范围、文件版本、规范和共享基线是否仍有效。满足条件可复用，只补缺失或变化的部分；错误事件本身不强制四步重载。无法判断有效性时执行下述恢复，不以 MCP 连接、会话 ID 或读过标记推定可复用。写入结果未知、CAS 冲突或并发变化仍按第三步核对实际结果，不能以复用调查为由跳过。

1. **执行卡。** 核对本轮身份、完整范围、当前域及相关共享条目，包括 Module 归属、selector/requestedScope、状态、evidence、coverage、outcome、主定义、visual、哈希、用户要求和[跨域基线](cross-domain.md)。确定最早未完成动作。工作区使用合并卡中的成员条目，worker 读取根作者指定的同一张卡。
2. **对应证据。** 从消费记录定位当前单元与相关共享事实，按[机器合同](evidence/machine-packet.md)请求精确 `module-authoring` context，再按[场景闭合](evidence/scenario-closure.md)及[语言适配器](evidence/language-adapters/index.md)回读当前方法体、装配、配置、SQL、测试和明确材料。核对双摘要及范围；`ready`、旧结论或文件首行不代表证据已读。失败、空、partial 或漂移时定向补证并保留原因，不重建 bundle，不重新调查无关的已验收模块。
3. **相关正文。** 读取本域路由、将编辑或引用的专题主定义、Module 场景、跨域主定义及人工材料。首次创建时确认文件确实不存在。未知写入先与原预期比较，区分未落盘、已落盘待验和冲突，不直接重放。保留原 CAS 基线；文件与卡片不一致时先核对原因，不能刷新哈希后覆盖或自动推进状态。
4. **适用规范。** 读取[当前阶段](index.md)和完整[框架](framework/index.md)，联读[布局](framework/layout.md)、[Surface](framework/surface-profiles.md)、[本地化](framework/localization.md)、[编辑](framework/editorial.md)、[图文](framework/visual-expression.md)，以及 [Domain](framework/deliverables/domain.md)、[Module](framework/deliverables/module.md)、[六专题](framework/deliverables/topics.md)中本域实际需要的详细合同；按需读取[样稿](framework/examples.md)。索引或上一个域的摘要不能替代适用规范。

读取前用文件清单或定向搜索定位真实路径，再按标题/行段限制输出并记录已读边界；截断后补齐缺失段，搜索无匹配只说明该查询未命中。CLI 参数以当前 checkout/安装版本的帮助为准，不凭历史拼写调用。复用记录须能对应同一证据双摘要、正文哈希和规范版本。

范围、证据、正文和规范一致后，从最早未完成动作继续。同一 Domain 未丢失上下文且证据仍可用时复用调查，不为不同专题重复扫描。

恢复 K5/K6 时沿用相同顺序，以共享产物取代“当前域”：K5 读约束计划、原始机制证据、使用者/反例及实际规范；K6 读 K4/K5 验收版本、跨域交接和概览。按工程主题或系统交接恢复精确查询，不强造 Module selector，不因进入共享阶段重跑各域取证。规范、下层主定义或概览在验收后变化时，只重新核对其消费者和相关图表。

## 中断与异常

- 入口先区分新任务与原任务续作；存在本轮未完成卡或明确续作要求时，不从 build/Scope 重启。历史卡不自动扩大本轮授权。
- 初始调查尚未建卡就中断：核对已有构建结果和调查记录，从实际未完成步骤接续。已尝试的 build 不重跑；结果不可确认时记录原因并回当前源码。
- 应有的原卡丢失、归属/selector 不明或必需规范不可读：保留现有成果，报告缺失位置与待恢复信息，不从输出拼装缩小的全 reviewed 卡。
- 发现跳过恢复顺序：暂停本域续作，补做四步加载并核对期间修改；worker 将差异交根作者处理，不把漏读记作已执行。

恢复本身不重置状态、不重写已验收正文；只对实际变化或未完成验收重开受影响范围。未知写入、冲突和视觉待验项处理完成前保留原卡。
