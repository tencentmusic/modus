# 写作执行策略

本文件组织作者如何使用现有合同，不新增正文规范、状态、执行卡或工具协议。[证据](evidence/index.md)决定可主张的事实，[框架](framework/index.md)决定产物和表达，[发布合同](publication.md)决定验收与安全收尾。策略调整不能降低这些要求，也不能改变用户授权范围。

## 在现有阶段内组织工作

执行顺序与阶段出口由[六阶段入口](index.md)维护。K2 先规划全局依赖与当前页读者任务，K3/K4 按契约组、对象或完整场景交替取证、写作和回读，K5 独立提炼项目约束，K6 消费领域和规范结果组装系统入口并收尾。每次完成可恢复单元即保存，避免把全部编辑和验收留到最后。

这是关注顺序，不要求不同模型、多个 agent 或每步单独调用。局部 update/sync 只执行与受影响页面有关的动作，不新建初始化卡或读取 bundle。

一次单元应能完成“取证 → 相关主定义 → 场景/案例/图 → 跨页对账 → 检查点”。例如处理恢复入口时，同时补齐其接口条件、对象保留字段、恢复规则、状态转换及模块操作，不先写全域所有 API、再重新调查全域所有对象。文件是事实主落点，不是源码调查的批次边界；共享定义先稳定，其他场景随后复用。

工作记录按[事实投影](evidence/scenario-closure.md#从机器线索到正文主定义)保留来源、条件、主定义和使用处；共享事实改变时只重开受影响单元。单元完成不等于整页或整域完成：原卡保留尚未写入的条目，专题全量对账、逐篇回读、实际预览和域级覆盖仍按 K4 出口执行。这样既利用刚读取的细节，又不会把后续接口、字段和模块从范围中消失。

## 上下文与样稿使用

进入或恢复 Domain 时，按[逐域加载](evidence/scope-modeling.md#逐域加载与恢复)补齐权威状态、证据、相关正文和适用合同，仍完整有效的内容可复用。样稿是额外校准，不能替代合同或源码；同一上下文中已读且仍适用的样稿也可复用。

从[样稿索引](framework/examples.md)按当前问题选择片段，例如宽表、异步完成或恢复，不一次加载全部案例。只迁移解释方式，不迁移示例的字段、角色、状态、接口、数量或业务规则。先把当前证据讲完整，再参考样稿编辑，避免从样稿反向寻找相似事实。

上下文容量、检查点、压缩摘要保留项与意外恢复统一执行[上下文保存与恢复](context-continuity.md)。完整 Domain 是正文所有权单位，契约组、对象或场景是上下文工作单元；上下文变短不能成为删减后续领域内容的理由。

## 独立读者测试

独立读者用于发现作者因熟悉背景而漏写的解释。首期优先用于样稿校准、复杂或反复返修的域；普通页面仍必须执行完整的三类读者回读。能否使用独立读者不改变正文验收要求。

宿主支持且本轮允许委派时，使用没有作者对话和源码上下文的新读者；也可由人工独立阅读。独立读者只接收目标正文、允许访问的知识链接和预先准备的问题，不接收作者解释、事实底稿或标准答案。不得仅由当前成稿出题，否则遗漏的内容可能永远不会被检查。

可复用以下任务内容，按真实场景替换问题：

> 只依据给定成稿及其允许访问的知识链接，回答这些读者问题。每个答案指出文档中的段落或标题依据；缺少信息时明确指出缺口，不用通用常识推测。另列术语歧义、互相矛盾的陈述和无法继续完成任务的位置。不要修改文件。

问题应涉及读者的实际判断，例如成功返回后怎样确认完成、重复操作会怎样、字段修改影响什么、异常后由谁恢复。作者或事实审核者再用证据核对答案；读者能复述错误文档不代表事实正确。

返回问题位置、影响、证据或缺失内容、建议修订，不要求综合分。工具或授权条件不允许独立测试时，记录未执行并完成可做的回读；不能把同一作者角色切换称为独立测试，也不为启用策略反复要求用户确认范围。

## 策略更新与回归

稳定合同、样稿事实基线和执行策略分别评审。新策略先在相同源码快照、范围和模型上与原策略比较；换模型时先保持合同和策略不变。每次只改变需要评估的因素，记录实际模型/版本、策略版本、事实缺陷、读者任务结果、预览问题、修订成本和耗时。

维护者先使用普通域、复杂域标杆，再用没有参与调优的保留样本复核。生成者只接收输入和工作流，不读取参考答案或人工审核结论。主观比较隐藏版本并交换展示顺序，避免用更长正文、更多图或较新的模型名称代替质量判断。

重复出现的失败才值得调整策略；有普遍读者价值的规则再进入稳定合同。删去未带来改善的指令，不因外部 skill 更新直接追加整段提示词。回归使用具体缺陷和读者任务，不建立正文逐字快照、固定字数门禁或模型专属的竞争规范。
