# 写作执行策略

本文件组织作者如何使用现有合同，不新增正文规范、状态、执行卡或工具协议。[证据](evidence/index.md)决定可主张的事实，[框架](framework/index.md)决定产物和表达，[发布合同](publication.md)决定验收与安全收尾。策略调整不能降低这些要求，也不能改变用户授权范围。

## 在现有阶段内组织工作

1. **K2 规划阅读任务。** 在现有主定义/图形计划中记录全部目标页的读者问题、案例和表达安排。范围来自执行卡和证据，不从已写正文反推。此时安排是候选，K3 发现不同机制后原位修订。
2. **K3 闭合一次事实。** 精确加载各 Module，将入口族展开为逐接口清单、对象展开为逐字段集合，记录详情落点和未闭合项；按场景核对分支、权威写入、受理/完成和恢复。将同一事实投影到六专题与模块，不为各文件重复扫描。写前逐 Module/场景选图，不能用一项 Domain 导航表结束评估。
3. **K4 完成正文。** 沿六专题主定义、Module 场景、Domain 路由的既有顺序写作。每次完成一个契约组、对象或场景，立即对账并回读；长专题按语义分组或已有布局分片。先写完整条件、过程、结果和案例，再编辑排版，不先铺骨架后寄望一次性扩写。首个有图页面成稿后就按[渲染检查](framework/visual-expression.md#实际阅读与渲染检查)确认工具能力，并检查实际长表或长标识；及时修正后续页面的组织方式。当前域完成可做的验收并明确剩余项后再进入下一域。
4. **K4 编辑与核对。** 对当前页按[编辑合同](framework/editorial.md)调整段落、步骤、表格和图，并按[逐篇验收](publication.md#逐篇验收与事实对账)记录实际结果。先由清单查漏，再联读主定义、场景、图和案例核对同一事实，最后按[整页预览范围](publication.md#整页预览范围与未验证项)从页首到页尾查看、逐图核对，保存尚未查看的位置。发现新问题回 K3，修改后复核；不能把整个域的一句“已回读”当作逐篇记录。
5. **K5–K6 组装和收尾。** 校准跨域事实、术语、导航与完成口径，检查最终文件。局部问题只退回受影响域或页面，避免每轮从头重写。

这是作者的关注顺序，不要求不同模型、多个 agent 或每步单独调用。局部 update/sync 只执行与受影响页面有关的动作，不新建初始化卡或读取 bundle。

## 上下文与样稿使用

每次进入或恢复 Domain 仍按[逐域加载](evidence/scope-modeling.md#逐域加载与恢复)读取权威状态、证据、相关正文和完整适用合同。样稿是额外校准，不能替代合同或源码；同一上下文中已读且仍适用的样稿可以复用。

从[样稿索引](framework/examples.md)按当前问题选择片段，例如宽表、异步完成或恢复，不一次加载全部案例。只迁移解释方式，不迁移示例的字段、角色、状态、接口、数量或业务规则。先把当前证据讲完整，再参考样稿编辑，避免从样稿反向寻找相似事实。

为取证、成文和回读都保留工作预算。复杂模块需要更多上下文和篇幅时在域边界保存进度，不压缩后续模块为同长度摘要。上下文压缩后依照原执行卡恢复，不以模型记忆代替证据。

域太大时在契约组、对象或完整场景的边界保存当前页、剩余条目、未验收部分和下一动作，继续本域，不能等到全部文件写完才发现预算不够。worker 及时交给根作者写入原卡；压缩、容量/服务错误、工具中断或取消后续作都先实际读卡，再取证、读正文和加载规范。若中断发生在半个条目中，明确记录中断位置，不能把该条目标为完成；写入结果未知时先核对实际文件，不重放上一条修改命令。

## 独立读者测试

独立读者用于发现作者因熟悉背景而漏写的解释。首期优先用于样稿校准、复杂或反复返修的域；普通页面仍必须执行完整的三类读者回读。能否使用独立读者不改变正文验收要求。

宿主支持且本轮允许委派时，使用没有作者对话和源码上下文的新读者；也可由人工独立阅读。独立读者只接收目标正文、允许访问的知识链接和预先准备的问题，不接收作者解释、事实底稿或标准答案。不得仅由当前成稿出题，否则遗漏的内容可能永远不会被检查。

可复用以下任务内容，按真实场景替换问题：

> 只依据给定成稿及其允许访问的知识链接，回答这些读者问题。每个答案指出文档中的段落或标题依据；缺少信息时明确指出缺口，不用通用常识推测。另列术语歧义、互相矛盾的陈述和无法继续完成任务的位置。不要修改文件。

问题应涉及读者的实际判断，例如成功返回后怎样确认完成、重复操作会怎样、字段修改影响什么、异常后由谁恢复。作者或事实审核者再用证据核对答案；读者能复述错误文档不代表事实正确。

返回问题位置、影响、证据或缺失内容、建议修订，不要求综合分。工具或授权条件不允许独立测试时，记录未执行并完成可做的回读；不能把同一作者角色切换称为独立测试，也不为启用策略反复要求用户确认范围。

## 策略更新与回归

稳定合同、样稿事实基线和执行策略分别评审。新策略先在相同源码快照、范围和模型上与原策略比较；换模型时先保持合同和策略不变。每次只改变需要评估的因素，记录实际模型/版本、策略版本、事实缺陷、读者任务结果、预览问题、修订成本和耗时。

维护者先使用普通域、复杂域标杆，再用没有参与调优的保留样本复核。生成者只接收输入和工作流，不读取参考答案或人工审核结论。主观比较隐藏版本并交换展示顺序，避免用更长正文、更多图或较新的模型名称代替质量判断。

重复出现的失败才值得调整策略；有普遍读者价值的规则再进入稳定合同。删去未带来改善的指令，不因外部 skill 更新直接追加整段提示词。回归使用具体缺陷和读者任务，不建立正文逐字快照、固定字数门禁或模型专属的竞争规范。
