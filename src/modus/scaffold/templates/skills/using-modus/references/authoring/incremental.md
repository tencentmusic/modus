# 增量知识维护

`modus-update-knowledge` 与 `modus-sync-knowledge` 共用本流程。入口决定范围和权限，本页负责从变化追到主定义、消费者与发布结果；证据、正文质量和 CAS 仍由共享细则定义。

## 范围与权限

| 入口 | 变化依据 | 结构与人工内容 |
| --- | --- | --- |
| update | 用户明确要纳入的当前源码、事实或材料 | 复用已有授权；真实新增、拆并、迁移或退役合并确认一次；人工内容仅在明确委托范围内维护 |
| sync | 当前代码任务的实际变化，以及受影响场景内已证实的历史错漏 | 不接管已有脏改动；真实结构变化沿用授权或在当前任务合并确认；人工约束与业务资料默认保护 |

两者不构建或读取初始化 bundle，不运行全量 K1–K6，不创建或改写初始化执行卡，也不另建清单、回执、待办文件或持久状态。共享细则中的事实核对方法适用；初始化 selector、域级 coverage、执行卡及阶段状态不适用。必要的变化、证据和未决项只留在当前上下文或已有会话摘要，不要求固定表格或逐项工具调用。

中断后先核对本轮目标、读时哈希、实际已写结果与待验项，再读取相关当前正文；不能以最后一次工具报错推断整批未写入。上下文不足以恢复时说明具体缺口，不从生成文件反推整轮完成。复用已充分且仍有效的证据，不运行固定的无影响检查。

## 从变化到受影响正文

1. **从变化确定调查范围。** 以实际编辑、相关差异和当前源码/材料识别变化的能力与行为，覆盖新增、删除、移动及本轮已提交的修改。复用开发时读过的方法体、调用方、配置和测试；只补仍会改变结论的证据。已有知识、锚点和机械候选帮助定位，但不能作为完整场景清单；未命中时从实际入口、注册和调用者寻找业务归属，不能直接跳过。
2. **确定主定义并核对场景。** 读取相关完整正文、适用规范和源码，保存写前哈希。使用[证据指南](evidence/index.md)及[场景闭合](evidence/scenario-closure.md)核对事实，区分实现、要求、示例与推断。涉及共享能力时查明哪些实际业务入口使用它；涉及跨端、桥接或多种实现时核对真实注册及调用路径，只展开会改变该场景结论的差异，不从一端推断全部平台。行为条件变化沿初始状态、触发、分支两侧、可见结果和恢复核验，不能仅凭命名、签名、注释或测试存在判定行为。
3. **追踪实际消费者。** 从变化的接口、对象、规则、状态、资源或完成信号追到使用它的 Module、专题、Domain 路由及必要的根概览。跨域交接双向核对提供方与消费者的字段映射、已提交事实、完成与恢复责任。依赖无变化的契约即可判断下游不受影响时停止展开；仍存在会改变结论的未解析关系时继续定向调查或保留具体缺口，不能用固定跳数或候选为空宣告覆盖。未变化的主定义和导航保持原位。
4. **核对工程约束。** 工程机制变化时联读 Team Standard 的适用范围、依据、例外与验证方式；业务规则仍留在所属领域。默认保持 `initializeTeamStandard: false` 和 `allowTeamStandard: false`。明确委托维护或补建规范才选择 `allowTeamStandard: true`，按[团队规范合同](framework/deliverables/team-standard.md)定向核查当前证据；不能因文件缺失、仍是种子或实现已改变而自动获得权限。未获维护授权的规范偏差说明位置和影响，不靠改政策消除差异。
5. **原位修订并校准归属。** 按[生成框架](framework/index.md)与[编辑规则](framework/editorial.md)修订主定义、消费者和相关导航，同时修复该场景内已证实的历史错漏；不借此清理无关历史问题、补全全域模板或重排全库。既有 Module 能承载同一责任与业务结果时复用稳定身份，不因新增文件、平台变体或锚点移动新建模块。校验、阈值、优先级或执行顺序变化时，重算已有正反例首先命中的分支，联读步骤、表格与图；可运行的关键例子用当前实现复核。按需参考[对照样稿](framework/examples.md)，不复制样稿事实、不追加日期式 changelog。事实与正文已一致则跳写，不能为表示同步而制造修改。
6. **处理真实结构变化。** 按[Scope 建模](evidence/scope-modeling.md#结构变化)判断新增、拆并、迁移或退役，沿用已有授权；未获授权的决定按下节在当前任务合并确认，不要求用户切换维护命令。先建立并回读新落点、修复入链和导航，再按原哈希退役旧生成文件；符号或文件消失不能单独证明能力退役。新增已确认 Domain 后，用 `modus knowledge seed-business --domain <slug> --json` 补齐缺失索引，保留已有人工材料。

源码关联与正文在同一轮维护。按[源码关联约定](framework/layout.md)核对受影响
Module、专题及分片的 `anchors.locations` 和 `anchors.paths`。文件移动或改名时，
从本轮编辑与差异保留旧、新路径；调用只读 `modus knowledge sync` 时把两者都作为
变更路径提供，不能只传新路径而遗漏仍引用旧路径的文档。该命令仅返回候选，不写文件头。
只提供新路径或新增代码未被锚定时，继续沿真实入口和消费者确定归属。

确认仅位置变化时修订路径、符号或行号；行为变化时同时修订相关正文、案例和必要导航。
删除、拆分或重载变化须核对当前责任及声明，不能按同名自动替换或因旧符号消失删除文档。
写入后回读当前源码与文件头，确认相关旧引用已处理；未解决的关联缺口仍属未完成。

## 增量结构确认

只确认尚未授权的真实 Domain/Module 结构变化。用当前对话说明受影响的领域、模块名称与稳定 ID、原归属 → 建议归属、依据及受影响的消费者/导航，供用户一次确认或调整；需要理解决定的相邻责任一并说明，不要求全项目结构表或初始化确认卡。确认前可完成不依赖该决定的维护，但不先发布待确认结构；确认后在当前任务继续写入、修链和验收。已有完整授权直接复用，普通事实修订、补漏、标题/分片及锚点调整不另行审批。

## 验收与发布

按[发布合同](publication.md)完整回读所有受影响页面及关联上下文，用具体读者任务核对能否独立理解。先从本轮变化和源码新发现的场景核对事实是否有正确落点，再由正文反查条件与证据，不能只沿已经写出的内容自查。关键结论须与当前源码及适用配置一致；实现验证失败时只写已确立的行为或失败事实，不能把期望结果写成成功。取证后相关源码或知识发生变化时重验受影响结论，不靠旧测试或旧回读收尾。

变化的图表和版式实际预览，修复后重看；工具不可用时说明具体页面、未验项和影响。独立读者仅在已有委派授权和隔离上下文可用时增强验收，不以自查冒充。

使用读时哈希提交 CAS 写入，回读实际字节后对每个受影响 Domain 运行 `modus knowledge verify --domain <slug> --json`。涉及根概览、跨域迁移或共享导航时，运行普通 `modus knowledge verify --json` 检查共享链接；这是只读机械核验，不授权重写其他域。局部维护不使用要求初始化执行卡的 `--publication`。

请求被拒绝时先修正输入；逐文件冲突时保留已成功写入，查看 `conflicts` 与 `deferredDeletions`，只重读和重新判断受影响目标，不能刷新哈希后盲目覆盖。能够在当前任务解决的问题继续处理，冲突或工具报错本身不是交付终点；持续并发、确实不可得的证据、工具不可用或未获授权的决定阻止继续时，说明具体限制及下一动作，不盲目重试。

结束前区分三种结论，不新增状态文件或评分：

- **无需写入：** 本轮变化已核对且没有未解决项，无长期影响或受影响事实与正文已准确一致；sync 静默结束，不输出 noop。
- **同步完成：** 本轮受影响变化均已得到知识落点或有依据的排除，相关主定义、消费者和导航一致，实际写入已回读且必要核验完成，没有未解决项；简要报告实际变更和验证范围。
- **仍未完成：** 存在未查明的影响、待确认结构、写入冲突、规范偏差或未验证项；报告已完成范围、具体缺口及所需决定/证据/恢复动作，分别说明代码与知识状态，不以机械 `clean`、候选为空或无写入宣告同步完成。

本流程维护当前任务及其受影响场景，不保证发现从未触及的历史盲区，也不提供独立于会话上下文的自动恢复保证。
