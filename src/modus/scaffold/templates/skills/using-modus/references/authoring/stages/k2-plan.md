# K2：创作计划

先为全范围确定共享边界，再为当前完整 Domain 安排可恢复的写作单元。计划写入唯一执行卡正文，不新增 schema、状态或平行回执。

## 输入与必读

- 输入：K1 已确认范围、完整材料清单、现有正文与保护路径。
- 读取[范围与执行卡](../evidence/scope-modeling.md)、[上下文保存与恢复](../context-continuity.md)、[跨域协作](../cross-domain.md)。
- 读取[框架](../framework/index.md)、[布局](../framework/layout.md)、[运行形态](../framework/surface-profiles.md)、[编辑合同](../framework/editorial.md)、[执行策略](../execution-strategy.md)。
- 按 [K4 的必读表](k4-domain.md#输入与必读)加载本域实际产物合同，规划阶段也不能只读索引猜测验收要求。
- 全局计划联读 [K5 项目约束](k5-constraints.md)与 [K6 系统概览与发布](k6-publish.md)：规范记录按路径/平台选择的模块与待核验条件、编码场景、原始证据入口、复用能力、使用者和反例；概览记录读者问题与系统关系，等待 K4/K5 最终结果后才成稿。

## 执行

1. 列清全部 Domain、六专题及分片、Module、路由与共享产物。全局 K2 先登记清单、身份、路由与共享事实；进入当前域/工作单元后完整读入将编辑或引用的文件并记录写前哈希、人工保护范围，避免全库正文同时常驻上下文；reinit 标明 unchanged、anchor-only、implementation-change、scope-change、content-repair 或待证实退役，不把文件存在当作质量合格。
2. 按[初始化质量要求](../framework/index.md#初始化质量要求)给各页安排读者问题、事实主落点、贯穿案例与图文分工。为每份状态、协作文档和每个模块登记配图目标；范围内的其余图表按真实复杂度安排。保留目录、标题层级、元数据和有价值的人工正文。
3. 在原卡中建立可定位的材料、接口、对象字段、规则、场景与目标页对账记录；K3 补齐精确集合。项目共享机制单列 K5 使用处，包含不属于业务 Module 的构建、CI、配置与装配证据；业务不变量仍落域/模块。为实际高频任务规划默认写法与必要示例，如值/集合/转换、方法组织、公共能力复用、批量并发、DB 与配置；按项目存在的场景选择。保留调优样稿之外的验证任务及预期行为，K5 用它检验编码效果。规划来自范围和证据，不能从已写文件反推。一个事实只有一个主定义，模块保留理解完整场景所需解释并链接专题。
4. 按[机器消费路线](../evidence/machine-packet.md#六阶段消费与可恢复记录)读取相关 service-boundary/serviceRelation，结合双方源码核验，再按[跨域协作](../cross-domain.md)先明确事实所有者、交接契约与依赖顺序。先解决会影响其他域的接口、对象、状态、术语和完成口径，再安排消费者；未决交接影响的正文不能提前定稿。
5. 默认串行完成一个 Domain 的 K2 → K3 ↔ K4，再推进下一域。按契约组、对象或完整场景拆小工作单元，为取证、成文、回读、保存分别留空间；不先铺全库骨架。仅在已授权时读取[并行协议](../parallel-domain-authoring.md)并使用固定[委托合同](../domain-worker-prompt.md)。

## 产出与出口

当前域的精确目标、主定义、依赖、检查点与验收安排可独立恢复后，进入 [K3 证据闭环](k3-evidence.md)。规划不等于证据 ready；新发现的结构变化回 K1，域内证据和图表安排随 K3 原位更新。
