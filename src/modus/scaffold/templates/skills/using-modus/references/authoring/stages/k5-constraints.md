# K5：项目约束

根作者从前序已核验事实中提炼、编写并验收 `constraint/team-standard.md`。领域与模块说明业务如何运行，本阶段同时提供工程边界、复用导航与有条件的默认写法，让读者能实际落笔。已有规范从 K1 起读取并遵守；新规范在领域成稿后集中创作，系统概览留给 K6。

## 输入与必读

- 输入：K1 的技术栈、材料与规范状态；K2 的约束计划、保护范围与哈希；K3 的机制、配置生效链、反例和未决项；K4 的领域/模块成稿与逐篇验收结果。
- 读取[团队规范](../framework/deliverables/team-standard.md)、[约束提炼](../../../../modus-init/references/constraint-extraction.md)、[机器消费](../evidence/machine-packet.md)、[跨域协作](../cross-domain.md)、[发布合同](../publication.md)。按[模块索引](../../../../modus-init/references/constraint-profiles/index.md)和[选择与组合](../../../../modus-init/references/constraint-profiles/composition.md)复核 K2/K3 的选用记录，只加载适用主题，不把参考项目政策复制过来。
- 机器输入仍属于 K1 的同一证据会话。前序正文提供事实导航与适用范围，规则成立仍须追溯原始源码、配置、测试、CI 或明确材料。

## 执行

1. 回读实际规范并核对 K1 状态与读时哈希。首次 init 只填充 `missing` 或 `framework-seed`；`retained-content` 保留，`unavailable` 具名记录。reinit 默认只复核适用性与偏差，缺失也不自动补建。明确委托维护时沿用既有授权与结构；状态和文件名都不授予覆盖权。
2. 按 K2 的约束主题定位 K3 事实及 K4 使用者，复用同源 `constraint-extraction` signals、navigation、witnesses 与双摘要。只有存在未解决的机制、使用者或反例问题时，才按源码 candidate/capability/path/symbol 定向补查。不得用生成的知识路径查询机器包，不重跑 build。项目共享的构建、CI、装配和配置可能不属于业务 Module，须独立核查，不能因领域已完成而漏掉。
3. 沿“机制定义 → 实际使用者 → 强制检查 → 旁路/反例”核对适用范围。区分源码事实、明确约束、归纳约定、通用建议与待确认事项；多数模块的相同写法不能证明全仓必须如此。共用客户端只能支持已核验范围的默认复用，必须使用还需声明或已生效的强制机制。
4. 组合已核验模块：排除不兼容版本/平台，按来源、范围与规则性质处理冲突，相同语义共用主定义；不能按加载顺序或目录深度覆盖。按项目真实机制组织正文，逐条说明目的、性质、范围、触发、要求、依据、合法例外、失败影响和验证。对高频场景回答“什么时候用 → 默认复用谁 → 怎么写 → 关键边界 → 何时换方案 → 如何检查”。补齐方法/条件、格式/注释、值/集合/转换、公共能力、并发、DB、配置中的真实需求。复杂场景给有版本与真实依赖前提的示例，简单规则保持简短；示例同时满足所有适用规则。领域不变量留在域 `rule.md`，模块专属条件留在场景；共享工程要求在本页定义一次，下层只解释差异并链接。
5. 用 K2 保留的独立编码任务回读：从任务/路径导航到规则、复用入口、前提、示例与例外，给出具体实现或修改草稿，核验真实 API、接受的写法、失败边界、无关依赖与冗余抽象。冲突/版本不匹配作为负例；按授权运行适当检查，未运行如实记录。篇幅、关键词或链接通过不能代替编码效果。再用具体改动回读每条约束：读者能否确定改哪里、复用谁、保留什么、失败如何传播、怎样验证。与 K4 最终正文逐项核对适用边界；发现事实冲突回相关 K3/K4 定向修复并重验，不通过删掉人工政策消除偏差。未证实的项目要求不能进入当前规则；有适用条件的通用建议可以进入，但不能宣称已采用。
6. 按[写入协议](../publication.md#cas-发布)执行锁与 CAS。首次填充使用 `initializeTeamStandard: true`，保持 `allowTeamStandard: false`；维护既有内容使用独立授权，不能把首次填充失败升级为维护权限。有专题时先发布并确认专题全部成功，再单独更新入口导航。成功后回读实际字节、链接与适用范围，在原卡正文保存规则处置、验收版本及偏差；不新增 schema、候选文件或平行回执。

## 产出与出口

首次规范已完成并回读，或既有规范已保留并核对适用性后，进入 [K6 系统概览与发布](k6-publish.md)。reinit 中规范缺失且未获补建授权时，记录保持缺失的处置与影响，同样可继续；不将其记为已创作，也不生成悬空链接。交接明确实际文件版本或缺失状态、规则主定义、适用范围、未决偏差及允许概览引用的必要摘要。不可读规范或未修事实冲突保留下一动作，不能记录为完成；未变规范跳写。系统概览消费这些结果，不复制规范全文。
