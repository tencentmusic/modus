# 知识库生成框架

本目录是正文产物的唯一语义来源。Markdown 本身就是可审阅的规范源码；安装过程不从 Python 注入标题、Surface 文案或完成问题。

```text
事实集
  + 稳定布局与产物职责
  + union(Surface Profiles)
  + 目标自然语言
  = 当前项目的正文表达
```

## 规范强度

- **必须/不得**：身份、所有权、证据或读者任务的验收边界。
- **应**：高质量默认；有明确事实理由时可以采用更合适的表达。
- **可以**：按复杂度选择的增强。

不以固定字数、H2/H3 数量、图数、接口数或评分代替质量判断。

## 阅读路由

init/reinit 每次进入或恢复 Domain 时，先按[逐域加载与恢复](../evidence/scope-modeling.md#逐域加载与恢复)读取本域执行卡、对应证据和相关已有正文，再加载本框架及适用的详细合同；上下文压缩后不能用规范摘要替代实际读取。

- 先读[稳定布局](layout.md)和[本地化与通用表达](localization.md)，按其中的[术语解释、行为表达与来源追溯](localization.md#术语解释行为表达与来源追溯)规则组织正文。
- 联读[正文编辑与阅读排版](editorial.md)，先安排当前页面的读者问题、案例和信息分块；按实际问题选读[成对样例](examples.md)，不把样例事实或标题套入项目。
- 按运行入口组合[Surface 画像](surface-profiles.md)，不要按语言选择正文模板。
- 按产物读取[根概览](deliverables/root.md)、[Domain](deliverables/domain.md)、[六专题](deliverables/topics.md)、[Module](deliverables/module.md)及特殊人工产物合同。
- 复杂关系再读[图文表达](visual-expression.md)。

事实只在一个主落点完整定义。其他页面说明该事实在当前上下文中的作用，并精确链接主定义；不得复制整段定义或完整 Mermaid。源码位置只写入生成文档 frontmatter 的少量 `anchors.locations`；读者正文不出现完整源码路径、行号或证据清单。

## 内容形成节奏

高质量正文通常遵循“总览定位 → 真实条目/场景详情 → 解释型图表 → 失败与恢复 → 修改和验证入口”。表格不是为了凑格式，而是承载字段、条件、状态或责任的精确对照；图不是装饰，而是解释正文难以快速表达的方向、层次和时序。

写前依据已闭合事实确定表达安排，写后逐篇编辑并检查实际阅读效果，再按[发布合同](../publication.md)验收。具体批次、上下文与独立读者组织方式见[执行策略](../execution-strategy.md)；策略不改变本框架的质量要求或已有状态与权限。

每个 Domain 都必须先把六专题、Module 和路由写完整并回读，才算一个可验收批次。默认依次完成；用户明确授权且宿主支持时，互不重叠的完整 Domain 可以按[并行撰写协议](../parallel-domain-authoring.md)由不同正文所有者并行，但同一 Domain 内仍按唯一主定义共同闭环。不得先批量生成同长度短文、统一三段式骨架或只有类名与行首锚点的“已完成文件”。作者在每个产物的专用合同中回答具体读者问题，不能只阅读本索引后凭通用模板写作。
