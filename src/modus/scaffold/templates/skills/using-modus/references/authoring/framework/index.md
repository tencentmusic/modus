# 知识库生成框架

本目录是正文产物的唯一语义来源。Markdown 本身就是可审阅的规范源码；安装过程不从 Python 注入标题、Surface 文案或完成问题。

```text
事实集
  + 稳定布局与产物职责
  + union(Surface Profiles)
  + 目标自然语言
  = 当前项目的正文表达
```

## 规范强度

- **必须/不得**：身份、所有权、证据或读者任务的验收边界。
- **应**：高质量默认；有明确事实理由时可以采用更合适的表达。
- **可以**：按复杂度选择的增强。

不以固定字数、H2/H3 数量、图数或评分代替质量判断。实际范围内的接口与字段仍须逐项完整对账；不设固定接口数不等于可以抽取代表项。默认提供详实手册，篇幅随业务复杂度增长，以完整条件、解释和案例充实内容。

## 初始化质量要求

init/reinit 以事实准确、业务完整、解释充分、案例具体、图文一致和阅读顺畅为完成标准。范围包括全部已确认业务域、`references/`、`modules/` 及关联知识，逐篇检查，不能只深化少数代表页。资料调查按[材料覆盖](../evidence/index.md#材料覆盖)执行，内容与当前源码、配置、既有知识和用户背景交叉核验。

- 每类文档按职责展开业务背景、目标、角色、触发与前置、操作、规则判断、输入输出、数据变化、完成条件、上下游影响和异常处理。根据实际适用性组织，不能机械套用空标题；重要结论有可定位依据和复核方法。
- 当前实现、明确业务要求、示意案例和待确认事项分别表达；示例数据明确标注。来源冲突或缺失写出对结论的影响，未调查内容不能写成“不适用”。
- 每个 Module 至少一个贯穿案例及一张关键流程图；每份 `state_machine.md` 至少一张状态图或流程图；每份 `downstream.md` 至少一张依赖、时序或数据流图。图前说明问题，图后解释关键条件和完成/失败。明显不同的路径分别展开，更多图按复杂度安排。
- 无持久状态时画真实处理阶段，无远端协作时解释已核验的本地/宿主边界；不能为配图编造状态或参与者。确无证据形成所需图时保留具体缺口，不能以 waived 冒充要求已兑现。模块场景投影与专题机制图可以互补，不复制完整主图。
- 保持既定目录、标题层级、元数据与格式；新建遵循对应合同。术语、状态名、指标口径和示例标识跨页一致，重复内容明确主落点并链接，保留有价值的人工内容。
- 按[发布合同](../publication.md)逐篇回读与对账，检查链接、源码引用、表格、元数据，实际验证 Mermaid 渲染及布局。发现简略、套话、遗漏或图文冲突就继续修订，交付分别说明覆盖、实际验证和缺口。

上述配图和案例是初始化/全量重建的交付要求，不是机械图数评分。update/sync 只处理获授权的受影响范围，不因这一要求扩成全库补图；用户明确调整交付要求时记录并遵从，事实与写入边界仍有效。各类逐项细则由[六专题](deliverables/topics.md)及[Module](deliverables/module.md)合同维护。

## 阅读路由

init/reinit 进入或恢复 Domain 时，按[逐域加载与恢复](../evidence/scope-modeling.md#逐域加载与恢复)判断哪些内容可复用、哪些需要加载。本域执行卡、证据、相关正文与适用规范仍完整有效时只补变化；上下文丢失后实际恢复，不能用规范摘要替代原文。

- 先读[稳定布局](layout.md)和[本地化与通用表达](localization.md)，按其中的[术语解释、行为表达与来源追溯](localization.md#术语解释行为表达与来源追溯)规则组织正文。
- 联读[正文编辑与阅读排版](editorial.md)，先安排当前页面的读者问题、案例和信息分块；按实际问题选读[成对样例](examples.md)，不把样例事实或标题套入项目。
- 按运行入口组合[Surface 画像](surface-profiles.md)，不要按语言选择正文模板。
- 按产物读取[根概览](deliverables/root.md)、[Domain](deliverables/domain.md)、[六专题](deliverables/topics.md)、[Module](deliverables/module.md)及特殊人工产物合同。
- init/reinit 和涉及图表的局部维护读取[图文表达](visual-expression.md)。

事实只在一个主落点完整定义。其他页面说明该事实在当前上下文中的作用，并精确链接主定义；不得复制整段定义或完整 Mermaid。源码位置只写入生成文档 frontmatter 的少量 `anchors.locations`；读者正文不出现完整源码路径、行号或证据清单。

## 内容形成节奏

高质量正文通常遵循“总览定位 → 真实条目/场景详情 → 解释型图表 → 失败与恢复 → 修改和验证入口”。表格不是为了凑格式，而是承载字段、条件、状态或责任的精确对照；图不是装饰，而是解释正文难以快速表达的方向、层次和时序。

写前依据已闭合事实确定表达安排，写后逐篇编辑并检查实际阅读效果，再按[发布合同](../publication.md)验收。具体批次、上下文与独立读者组织方式见[执行策略](../execution-strategy.md)；策略不改变本框架的质量要求或已有状态与权限。

每个 Domain 都必须先把六专题、Module 和路由写完整并回读，才算一个可验收批次。默认依次完成；用户明确授权且宿主支持时，互不重叠的完整 Domain 可以按[并行撰写协议](../parallel-domain-authoring.md)由不同正文所有者并行，但同一 Domain 内仍按唯一主定义共同闭环。不得先批量生成同长度短文、统一三段式骨架或只有类名与行首锚点的“已完成文件”。作者在每个产物的专用合同中回答具体读者问题，不能只阅读本索引后凭通用模板写作。
