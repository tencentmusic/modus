# 模块契约

- **读者任务**：围绕真实任务说明一个功能模块怎样产生业务结果。
- **结构**：稳定路径 `references/modules/<module>.md`；推荐从“定位与边界 → 核心场景 → 实现、扩展与验证”展开，但可按事实自然组织。
- **证据**：implemented Module 在 frontmatter 的 `anchors.locations` 保留最小充分、仓库相对、带限定符号的代表性源码位置；正文不出现源码路径、行号或“证据”清单。锚点用于漂移校验，正文负责解释入口、判定、权威写入、完成/失败、恢复和验证。不得把大量位置搬进 frontmatter，也不得要求开发者打开源码才能理解正文。文件首行只有在声明本身位于首行时才是行为证据。明确 `realization: business-only` 的 Module 不伪造源码锚点。
- **适配**：Surface 决定场景重点，Language Adapter 决定取证方式，目标自然语言决定表达。

九类 concern 是回读问题，不是九个固定章节：boundary、scenario、data-state、public-entry、collaboration、runtime、constraint、recovery、implementation。没有适用事实时不生成空章节或隐藏 coverage receipt；在自然语言中说明已核验范围即可。

每个非平凡核心场景用真实任务命名 H3，并依次回答目标、触发与输入、前提和关键判定、编排与权威写入、返回/异步交接、最终可见结果、失败残留与恢复、修改与验证入口。场景总览表只负责导航，不能替代这些详情。触发者、结果、权威写入、完成口径或恢复方式不同，就应拆成不同场景。

异步场景必须区分提交、消息发送、消费、下游完成和最终可见；复杂场景使用[图文合同](../visual-expression.md)中最小有用的图或表。共享契约/对象/规则在专题定义一次，Module 解释它们如何参与当前场景。

每个模块至少用一个明确标注的贯穿案例展示目标、输入、关键判定、数据或状态变化、最终结果和完成条件。案例必须符合已核验事实；不同操作路径的责任、结果或恢复方式不同就分别说明。模块保留独立理解本次任务所需的对象作用和规则条件，再链接完整专题；不能用“详见”替代过程，也不能复制整套字段字典。段落和步骤的组织参见[场景编辑样例](../examples.md#从清单到场景)。

## 从导航到工程手册

一份可独立阅读的 Module 通常需要自然覆盖以下内容，标题可以按项目语言和事实调整：

1. **定位与边界**：服务角色、解决的问题、拥有的结果、不负责的相邻能力。
2. **场景地图**：用表格列出真实任务、触发入口、完成信号、主要失败点和详情锚点。
3. **核心场景**：逐个 H3 展开端到端行为；不能把创建、提交、回调、查询套用同一段通用描述。
4. **对象与状态**：指出本场景使用哪些权威对象、业务键、状态、金额/时间/身份字段，以及它们的主定义链接。
5. **接口与协作**：解释公开入口、消息、任务和下游怎样参与当前任务，返回成功是受理还是完成。
6. **规则与例外**：列出改变结果的前提、顺序、短路、安全边界和合法例外。
7. **运行与恢复**：资源/配置依赖、故障现象、失败残留、自动恢复和人工处置边界。
8. **实现、扩展与验证**：用职责、限定符号或协议身份说明修改入口、扩展点、兼容风险、测试与观测方式；精确源码位置只在 frontmatter。

推荐的场景总览表：

| 场景 | 触发与角色 | 权威结果 | 完成信号 | 失败/恢复 | 详情 |
| --- | --- | --- | --- | --- | --- |
| 真实任务名 | 谁通过什么入口发起 | 写入或产物 | 调用者最终看到什么 | 残留与处置 | 本文锚点 |

## 核心场景展开

每个场景沿同一条证据链说明：

```text
角色与目标 → 触发/输入 → 前提/权限 → 关键判定与分支
           → 编排/权威写入 → 同步返回或异步交接
           → 最终可见结果 → 失败残留/恢复 → 修改与验证
```

需要特别说明：

- 输入字段如何影响分支，缺省、空值、零值和特殊枚举是否不同；
- 判定发生在事务、锁或远端副作用之前还是之后；
- 哪个写入是权威事实，哪些只是日志、缓存、索引或派生视图；
- 异步发送成功是否等于业务完成，消费失败是否安全重放；
- 调用方应依据响应、状态、事件还是查询结果判断完成；
- 修改该场景时需要同步调整哪些契约、规则、状态、资源和测试。

## 图表选择

先确定图要消除的误解，再从下列形式选择。用户明确要求每个 Module 配一张关键流程图时，逐模块登记并兑现该要求；已有专题图不能直接豁免本模块，可以用不同视角的场景投影解释操作步骤和完成点，链接完整机制图。

- 多参与方或返回后继续执行：时序图，并在图下说明超时、重复、部分成功和最终完成。
- 持久状态变化：状态图或链接 State Machine 主图，并列转换条件与恢复。
- 多条件判定：决策表；顺序或副作用重要时补流程图。
- 多对象/多表示：关系或映射表，必要时链接 Object 主图。

模块全景表、类名列表和源码锚点只是调查与追溯信息，不能替代上述解释。不同 Module 若都呈现为相同的“三段概述＋若干方法名”，说明写作仍停留在批量骨架阶段。

完成标准：新人能复述一次完整操作，贡献者能安全修改或扩展，维护者能判断失败停在哪里以及怎样恢复。
