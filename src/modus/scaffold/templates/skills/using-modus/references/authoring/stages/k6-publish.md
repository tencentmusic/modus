# K6：系统概览与发布

先消费 K4 领域/模块成稿和 K5 规范结果编写系统概览，再完成全局核验与发布收尾。系统入口必须建立在最终主定义上。逐页写入安全从 K4 开始贯穿全程；本阶段分别证明内容、机械完整性和实际落盘结果。

## 输入与必读

- 输入：完整原执行卡、K4 全部成稿及验收版本、K5 规范与适用性结论、跨域交接、图形记录与剩余缺口。
- 读取[根概览](../framework/deliverables/root.md)、[团队规范](../framework/deliverables/team-standard.md)、[业务材料](../framework/deliverables/business.md)、[发布合同](../publication.md)、[初始化质量要求](../framework/index.md#初始化质量要求)、[跨域协作](../cross-domain.md)、[上下文保存与恢复](../context-continuity.md)。

## 执行

1. **核对系统交接。** 按[机器消费路线](../evidence/machine-packet.md#六阶段消费与可恢复记录)复用或定向展开 serviceRelation，结合当前源码反查提供方和使用方最终正文，也检查未进入交接表的关系。逐条核对方向、字段映射、权威所有者、已提交事实、完成信号及恢复责任。冲突回所属 K3/K4，涉及规范性质或适用范围回 K5；修复后重新接受受影响交接。
2. **编写系统概览。** 按根概览合同组织系统目标、角色、运行架构、能力关系、导航及开发排障入口。多 Domain 或多运行单元项目提供系统关系/运行图及交接表，选代表链路解释跨边界完成。引用 K5 已验收或保留且实际存在的 `team-standard.md`，只带理解系统所需的约束摘要和精确链接，不复制规则细节，不把待确认项写成系统保证。规范缺失时沿用 K5 的边界说明，不创建悬空入口。reinit 只改真实受影响的概览事实。
3. **完成共享导航。** 每个新增 Domain 使用一次 `modus knowledge seed-business --domain <slug> --json` 创建缺失索引，不手写种子；已有人工材料保持原位。结构迁移先建立并回读新落点、修复入链和导航，再按原哈希删除已证明退役的生成文件。
4. **全局语义验收。** 从已确认范围反查全部目标与材料处置，按[证据消费记录](../evidence/machine-packet.md#六阶段消费与可恢复记录)双向核对“记录/源码 → 事实 → 主定义/图/案例”。核对六专题及分片、全部模块、路由、规范和概览；不能从现有文件反推较小范围。跨域方向、规则条件、术语、状态、统计和完成/恢复口径须一致。按发布合同校准最薄、最新和最复杂的域，修复简略条目、套话和矛盾后回读。
5. **内容与视觉复查。** 核对内部链接、源码引用、表格、元数据与逐图结果。整页预览覆盖本轮新写/实质修订内容，包含本阶段概览；未实际渲染不得标通过。记录环境、未预览章节和图、影响及下一动作。
6. **机械核验与落盘回读。** 实际运行 `modus knowledge verify --publication --json`，核对原 `schemaVersion: 2` 执行卡的逐 Module evidence/status、Domain coverage/outcome、锚点与 visual 承诺。处理 CAS 冲突、跳过未变文件并回读实际内容，修复后重验。clean 不证明语义或视觉合格；冲突只回受影响目标，不刷新哈希盲目覆盖，不承诺整批回滚。
7. **发布收尾。** 全部确认目标终结、共享产物已验收、publication 和发布后回读通过，且整页/逐图验收无待修或待验项时，才删除原执行卡并仅清理空目录。卡片丢失不得按输出补造全 reviewed 卡；有待验或 blocked 项保留原卡。

## 产出与出口

报告实际写入、删除、未变更、冲突/跳过及原因、内容覆盖、机械结果、整页预览范围、逐图结果和剩余缺口。工具不可用时可以交付已完成正文并保留待验记录，但不能宣称全部验收完成；不为同一工具限制反复请求批准。
