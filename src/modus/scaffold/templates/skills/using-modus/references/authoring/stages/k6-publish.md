# K6：核验发布

分别证明内容、机械完整性和实际落盘结果；只报告实际执行的检查。逐页写入安全从 K4 开始贯穿全程，这里完成全局核验与收尾。

## 输入与必读

- 输入：完整原执行卡、实际最终文件、所有逐篇记录、图形记录与剩余缺口。
- 读取[发布合同](../publication.md)、[初始化质量要求](../framework/index.md#初始化质量要求)、[跨域协作](../cross-domain.md)、[上下文保存与恢复](../context-continuity.md)。

## 执行

1. 从已确认范围反查全部目标与材料处置，按[证据消费记录](../evidence/machine-packet.md#六阶段消费与可恢复记录)核对相关记录/源码 → 已核验事实 → 主定义页/图/案例的映射；歧义、省略、反证和跨域关系均须有处置，未闭合项不能用状态标签掩盖。核对域内逐篇验收已覆盖六专题及分片、所有模块、路由和共享产物；不得从现有文件反推一个更小的完成范围。
2. 做全局语义回读：跨域方向、对象/状态所有者、规则条件、术语、案例、链接及完成/恢复口径保持一致。按发布合同校准最薄、最新和最复杂的域；简略条目、套话、重复空泛内容或图文矛盾仍须回 K3/K4 修复。
3. 核对内部链接、源码引用、表格、元数据与逐图结果。整页预览须覆盖本轮新写/实质修订内容；未实际渲染或只看图源不得标通过。记录具体环境、未预览章节、图和影响，保留后续动作。
4. 实际运行 `modus knowledge verify --publication --json`，核对原 `schemaVersion: 2` 执行卡的逐 Module evidence/status、Domain coverage/outcome、锚点与 visual 承诺。修复问题后重验；普通 verify 或 publication clean 都不证明内容详实、机器查询实际执行、证据已经消费或视觉合格。
5. 按发布合同处理 CAS 冲突、跳过未变文件并回读发布后的实际内容。冲突只回到受影响目标；不能只刷新哈希盲目覆盖，也不能承诺整批回滚。
6. 只有全部确认目标终结、语义回读、publication 和发布后回读通过，且本轮整页/逐图验收没有待修或待验项时，才删除原执行卡并仅清理空目录。卡片丢失不得按输出补造一张全 reviewed 卡；有待验或 blocked 项就保留原卡。

## 产出与出口

报告实际写入、删除、未变更、冲突/跳过及原因、内容覆盖、机械结果、整页预览范围、逐图结果和剩余缺口。工具不可用时可以交付已完成正文并保留待验记录，但不能宣称全部验收完成；不为同一工具限制反复请求批准。
