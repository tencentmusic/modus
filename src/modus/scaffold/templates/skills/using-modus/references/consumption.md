# C1～C6：让知识参与当前任务

本页定义阶段衔接、停止条件与回跳判断；入口职责与执行节奏由 [using-modus](../SKILL.md#c1c6按任务消费知识) 定义。N1～N6 初始化证据处理、K1～K6 知识创作沿用各自工作流，日常消费不启动它们。

## 阶段衔接与恢复

交接只保留下一步需要的目标与范围、关键决定、证据位置、实际修改、待判断的知识影响和未完成验证，随当前上下文或已有会话摘要延续。已有结论仍适用时直接复用，不因进入下一阶段重新检索或重新验证。

恢复时核对任务范围及相关当前源码、正文与实际修改，从最早缺失或失效的判断继续。证据位置不明回 C2，内容不足或已经变化回 C3，目标或授权范围不清回 C1；不能还原的缺口如实说明，不宣称已经验证或同步。

## C1 任务定界

接收需求、对话、显式路径和本轮已核实事实，明确要回答什么、改变什么、保持什么；按[联合定位的适用范围](router-details.md#业务与工程联合定位)识别业务与工程证据缺口。

目标、范围及会影响结果的未知已明确，就停止定界：位置未知交 C2，已有材料待核实交 C3，证据充分可直接进入 C4。任务不依赖项目知识时按[激活边界](../SKILL.md#激活边界)退出本流程。

目标、范围或修改意图变化时回到本阶段，实际进入修改则建立[知识留存检查点](../SKILL.md#知识留存检查点)。不为知识库存在而扩大任务。

## C2 联合定位

围绕 C1 的缺口，按[路由与联合定位](router-details.md#路由)找到相关主定义、适用规范与实现入口；使用 CLI 时按[便利接口](router-details.md#便利接口)解释候选与续读位置。

已找到足以展开当前问题的具体条目或源码位置，就交 C3 核实，不继续收集同类候选。已有证据充分时可直接进入 C4；未命中或材料不可用时按[降级规则](router-details.md#降级)继续找替代证据，不能把空结果当作无需取证。

定位发现任务对象或范围与原理解不同，回 C1；仅缺少新消费者或相关规范的位置，留在 C2 补齐该范围。

## C3 证据收敛

对已定位材料按[证据读取与核验](router-details.md#证据读取与核验)补齐当前决定需要的内容，并按[性质与证据](constraint-usage.md#区分性质与证据)区分事实、要求、建议和待确认项。

关键结论有依据、适用条件清楚，且剩余未知不会改变当前决定时，停止取证并交 C4。仅支持局部结论时，保留结论的范围；会改变结果的缺口继续定向调查，需要用户决定或外部信息时明确其影响。

条目未读全或已有来源待核验，留在 C3；缺少新的证据位置回 C2；发现需求本身有歧义回 C1。

## C4 产出决策

接收 C3 的证据及其适用范围，按[从要求到决定](constraint-usage.md#从要求到决定)形成选择与验收依据，涉及冲突时按[继承与冲突处理](constraint-usage.md#继承冲突与应用)判断。

本次改变与保留的行为、关键取舍及结果如何核对已经明确，且没有阻止执行的未决问题时，交 C5。非代码任务交接的是解释、比较或诊断的组织依据，无需编造实现计划。

选择依赖尚未确立的事实，回 C3；新增方案引出未知能力或规范入口，回 C2；需要改变任务目标或授权范围，回 C1。未决问题只阻止依赖它的部分，其余已明确工作可继续。

## C5 执行与验收

按[落实与验收](constraint-usage.md#落实与验收)执行 C4 的决定，将实际结果与关键预期核对。

预期已兑现且必要验证完成，就结束本阶段。验证失败且原因、修复方向已明确时留在 C5；实际不能完成的验证要说明范围和影响，不宣称已通过。交付前按[知识留存检查点](../SKILL.md#知识留存检查点)判断是否进入 C6，未完成的验证也随实际变化交接。

出现新消费者、不同平台或新的失败窗口时，位置未知回 C2，证据不足回 C3，原决定失效回 C4。只重开受影响的判断，不因每次编辑重新跑整条流程。

## C6 知识留存判断

接收 C4 明确保留或改变的行为、C5 实际差异与验证结果，以及已找到的主定义、消费者和知识偏差，按[知识留存检查点](../SKILL.md#知识留存检查点)判断后续动作。

检查点判定无需同步时结束；需要调查或维护时交给 [modus-sync-knowledge](../../modus-sync-knowledge/SKILL.md)，由[增量维护的验收与结束条件](authoring/incremental.md#验收与发布)确定完成、无需写入或仍有缺口。

调查发现新的知识位置缺口回 C2，证据不足回 C3；若揭示实现不满足本次要求，回 C4/C5 修正并重验受影响结果，再判断知识影响。知识维护的权限与写入规则留在同步流程，不在本阶段另建一套。
