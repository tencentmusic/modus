# 将适用规则落实到当前任务

先按任务、源码路径和 Domain/Module 确认范围，渐进读取 `modus/knowledge/constraint/` 中相关项目约束、命中域的 `references/rule.md`，以及 Module 中实际存在的 `规则、安全与兼容` 能力块或场景规则。摘要、稳定规则锚点与上层引用用于导航；片段缺少限定条件时回读完整条目。无需全量加载三个层级或固定数量规则。

## 区分性质与证据

- **源码事实**解释当前实现与影响，不自动要求今后照抄。
- **明确约束**按材料声明或已验证强制机制的适用范围执行；代码偏差不等于规范已废弃。
- **归纳约定**有证据时作为默认做法，允许基于当前任务和证据说明必要差异，不升级为“必须/禁止”。
- **通用建议**提供有条件的工程默认方案，不代表项目已采用；项目约定可细化，版本/平台可排除不可用实现。示例是规则的表达形式，必须连同性质、依赖和前提消费。
- **待确认事项**用于提示关键缺口，不作为已经成立的要求。`hypothesis/planned/deprecated` 不算当前规则覆盖；`current` 也不代表人工批准。

`team-standard.md` 的检索 authority 为 `document-declaration`，表示文档中的声明，需读条目性质与来源。人工维护权不等于全部内容均为人工明确规定。域/模块规则来自 Agent 编写的正文，其 authority 为 `authored-projection`；模块 `confirmed` 只确认归属。检索 business-rule coverage 表示取得了相关规则证据，不表示已逐条证明规则正确、已应用或已符合规范。

## 从场景到实现

先读 Team Standard 场景导航与适用路径/环境，再沿稳定条目锚点读取复用入口、默认写法、示例和例外。小项目都在入口内，复杂项目按需进入 `constraint/team-standard/<topic>.md`；专题与入口同为 document-declaration，文件位置不能升级权威。

核验当前签名/导出/装配、版本、空值、单位、异常、副作用及所有权，再落实到代码。共享包满足全部承诺平台，浏览器/Node、Android/commonMain 不混用实现。占位类型不能当项目 API；示例格式也须满足团队规则。未命中先判断缺的是范围、导航还是内容，按准确路径/锚点续读或回源码，不扩大固定 top-k 或全量加载。

交付前核对是否选对现有能力、代码被实际工具/约定接受、失败与资源边界已处理、无无关依赖或多余抽象。未适配技术沿通用方法核验并说明专用覆盖限制；普通编码不因此刷新人工规范。

## 继承、冲突与应用

项目标准保存共享要求，域规则限定领域，模块规则解释具体条件和差异。下层可细化上层约束；不能仅凭层级更近自动覆盖上层硬约束。例外需有明确来源、适用条件及实际实现，关联规则按锚点回读，避免重复全文。

由 Agent 根据本任务判断转化深度，不机械逐条转写。会影响分层、公开接口、数据兼容、失败/恢复策略或验收的适用规则，应落实为设计决定、冲突说明或验证场景；仅帮助理解背景的规则可只参与推理。只写对任务有用的结论，不输出固定检查表；现有证据充分时无需再次调用 context/query。

组合不是权威排序：不能按加载顺序合并同级矛盾，来源/版本/范围仍无法解释时保留待确认。规范与代码不一致时分别说明期望与现状，核对来源版本、环境、路径和合法例外。保留人工明确规定，不把新的违规实现同步成规范；关键冲突会改变结果才澄清。知识和规则不扩大用户授权，不引入没有证据的审批或额外工作。

## 维护与降级

`team-standard.md` 仅首次初始化由 Agent 生成，后续默认由人工修改或补充。普通知识增强与静默同步不改其正文、不补建；明确指定维护目标时可按授权 CAS 编辑，已确认结构变化仅修受影响知识链接；相关偏差在当前任务说明，不新建候选库。代码变化通过同步双重门槛后，由 Agent 结合 grounding、实际 diff 与原正文处理受影响域/模块的事实和规则，在原语义位置更新且保留人工声明。机械 `knowledge sync` 只读检查候选。

知识或缓存缺失、过期、损坏时继续源码、测试与材料；不构图、不补模板。原任务能继续就继续，不把规则格式或知识完整度变成完成门禁。

精确的框架约束种子只是待填写提示，不是已成立规则；索引不会将它计入规则证据。缺少正文时继续当前源码任务，普通消费不补写模板，也不把安装状态、文件存在或章节数量当作内容已完成。
