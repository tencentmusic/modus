# 三层约束提取与证据核验

用于项目 `team-standard.md`、业务域 `references/rule.md` 和 Module 的规则语义。它是编写与回读的方法，不是新流程、自动分析引擎或知识发布门槛。首次项目标准另读[Team Standard 合同](../../using-modus/references/authoring/framework/deliverables/team-standard.md)；域与模块沿用[共享生成框架](../../using-modus/references/authoring/framework/index.md)。

## 按实际技术栈选读

从清单、锁文件、构建 target、启动装配和实际调用确认语言与框架版本，再读取相关指南。Profile、扩展名和依赖声明只提供线索；不能因为 Profile 未识别 PHP/C++ 服务就跳过实际入口。不全量加载所有指南，不把框架通用建议直接抄入项目标准。

## 从证据到可执行规则

1. **盘点工程证据**：声明材料、构建/依赖锁、源码与配置、IDL/DDL/迁移、测试、CI/CD、部署与运维说明都在调查范围。标出第一方实现、生成代码及其生成源、第三方、示例和遗留路径。生成文件可证明当前契约，不能作为手工修改入口或独立重复样本。
2. **追踪生效链**：入口 → 装配/中间件 → 编排/领域 → 资源操作 → 返回或异步交接。查谁提供身份与租户、谁拥有状态写入、事务在哪里结束、哪个调用带来外部副作用、失败传给谁。消息/任务/内部入口可能绕开 HTTP 校验，前端隐藏按钮不证明后端授权。
3. **找到公共机制及调用者**：配置工厂、共享客户端、基类、拦截器、仓储、类型和数据库约束、架构测试、CI 检查优先；再回读实际使用者和旁路。机制存在不证明所有代码都经过它，测试文件存在不证明检查在 CI 中启用。
4. **核对配置与失败路径**：追配置键的定义、绑定、注入、覆盖和读取点，区分默认值、环境值、调用点值与远程动态值。记录单位、关闭/无限等特殊值和已知覆盖关系；无法确定的生产配置明确未知。检查异常、超时、重复、取消、并发、部分成功、回滚、补偿和重放中相关场景。
5. **寻找反例并收窄结论**：同域其他入口、批量路径、旧版本、新旧框架并存及不同构建变体都可能是反例。将其区分为有依据的合法例外、明确规范下的历史偏差、或尚未解释的矛盾；未解释前缩小规则范围或降为事实/待确认。不能以多数票认定规范。
6. **落位并回读**：写到最小有效范围，链接上层规则与已存在的细节专题；从一次具体改动重新走查，确认读者能确定修改位置、复用能力、兼容影响及验证方式。缺证据就定向补查，不为了延长耗时或凑数量重复调查。

复用本轮已调查入口和确认卡中的业务范围；有效 init/reinit 先请求 `constraint-extraction` intent packet，再只对会影响规则判断的 candidate、capability、path、symbol 句柄定向取得 signals、navigation 和 witnesses，并保留双摘要、`requestedScope`、coverage receipt、omitted counts、resolution 和绑定强度。机器关系不能直接证明规则或实现结论；partial 只覆盖已读范围，候选调用不能当作运行调用。方法体、配置装配、SQL 与测试仍需直接读取；packet 未覆盖或源码已变化的文件使用 `rg` 和宿主工具。缓存不可用不会阻断创作，也不触发第二次构建。

## 规则性质与措辞

| 性质 | 成立依据 | 如何指导生成 |
| --- | --- | --- |
| 源码事实 | 当前可定位的实现、配置或调用链 | 描述现状及变更影响；单次实现不自动成为全局要求 |
| 明确约束 | 有出处的团队声明，或已验证生效的接口/数据/构建强制机制 | 在证据适用范围内使用必须/禁止；区分期望政策与当前执行情况 |
| 归纳约定 | 多个有代表性的独立路径体现共同机制，已核对反例与范围 | 作为新增/修改代码的默认做法，写“默认/优先”，不升级为硬约束 |
| 待确认事项 | 关键配置不可得、调用未解析、规范冲突或实现证据不足 | 说明具体问题及需要的证据，不作为已成立要求 |

模块 `state: confirmed` 只确认业务归属，不确认每一条规则。人工维护的文件也可能包含源码归纳；生成文档可以准确引用人工政策，二者不能凭目录互相升级权威。测试观察到一个行为只证明该测试的契约范围，不证明所有路径具备相同性质。

不得从“没有发现跨库查询”推出“禁止跨库查询”，也不得从依赖版本推出组织审批制度。无证据时不填 SLA、owner、生产超时、灰度比例、慢查询阈值、消息恰好一次语义或补偿能力。参考项目只能借鉴调查问题，不能复制其命名、数字、版本或基础类。

## 三层落位与继承

| 落位 | 应保留 | 避免 |
| --- | --- | --- |
| 项目标准的实际机制章节 | 跨域共享边界、公共机制、工程约定；局部栈要求明确路径范围 | 把单模块 TTL、状态或特殊外部协议提升为全仓规则 |
| 域 rule.md | 领域不变量、跨模块顺序/依赖、权威写入、域内工程限制、模块适用范围 | 通用语言教程，重复 infrastructure/downstream 的资源明细 |
| Module 的规则能力块或相关场景 | 当前入口/状态/资源的专属条件、复用要求、例外和验证 | 复制项目/域规则全文，为无规则模块生成占位能力块 |

域 rule.md 有真实规则时使用“规则总览 → 规则详情”，安全、例外或待确认只在有证据时增加。Module 的 `规则、安全与兼容` 块先给适用上层规则链接，再写模块差异；简单条件直接留在对应场景。详情链接既有资源、接口、下游、对象和状态专题的准确章节。

下层规则可细化上层要求，不能凭层级更近就推翻上层硬约束。合法例外需给出允许条件、来源、适用入口及实际兜底；没有审批、审计或补偿实现就不补造。多个范围共享时只保留一份完整规则，其余引用稳定锚点。

## 条目表达与渐进读取

每条规则以有业务含义的标题和稳定锚点呈现，避免流水号。将性质、状态、适用条件和核心要求放在条目开头，使独立检索片段不会丢失限定条件。复杂规则的子章节需重述关键限制或链接规则总述，不让反例脱离上下文变成推荐。

以下是写作格式，尖括号占位内容须替换成真实证据，不是新增机器 schema：

```markdown
### <有语义的规则名称>

<a id="item-<稳定规则标识>"></a>
性质: 归纳约定
状态: current
适用: <域/模块、源码路径、框架版本与触发条件>

要求: <默认复用谁、判定什么、按什么顺序执行、结果是什么>。
依据: <正文解释复核方法；源码坐标记录在 frontmatter anchors.locations，材料名称、版本及声明范围按其权限引用>。
例外与偏差: <已验证条件；无反例时说明本次核验范围，不声称全仓证明>。
变更验证: <已有测试/检查或明确的人工回查步骤，区分已执行与待执行>。
关联: <项目/域上层规则以及资源、接口或状态专题的链接>。
```

可合并自然语言字段，但不能省略影响判断的依据和条件。首次版本在文件引言记录源码 revision、未提交改动范围和材料版本；只记录已经读取的证据，不做全仓哈希。模块沿用已有 frontmatter，源码坐标使用现有 anchors.locations，正文解释规则与复核方法，不往严格 schema 塞新字段。

复用检索状态 `current/hypothesis/planned/deprecated` 理解已有内容；待确认条目写 `状态: hypothesis`。已被替代的生成规则从当前正文删除并修复引用，历史交给 Git；既有人工作者的 deprecated 标记不授权自动删除人工条目。状态只是证据可用性，不是强制程度或人工批准。不要把已确认规范与待确认设想放进同一不可分割条目；“待确认项”下的内容不能用于声称已有规则覆盖。

## 回读与持续维护

用具体变更核验“触发 → 约束 → 实施点 → 例外 → 结果 → 验证”，同时反查源文件、符号/行号和内部链接。审阅失败传播、租户/权限、类型/单位、事务/并发、资源与契约中本范围涉及的内容。源码只显示不安全历史写法时，不将其包装为默认约定。

没有最低条数、字数、重复次数、固定调查轮数或分数门槛。六类应调查，有证据才写要求；不适用或证据不可得时说明调查范围与缺口，不能空泛补齐。CLI/schema/链接检查不代替语义回读。

项目标准首次完成后默认由人工更新，普通 reinit/update/sync 保留实际字节，相关偏差只在本次结果说明，不创建候选文件或队列。用户明确指定维护时按授权 CAS 编辑；已确认结构变化只修受影响的知识链接，保留其余语义与字节。reinit 全量复核域和 Module 规则并按自适应结构生成当前完整终稿；update/sync 只更新本次变化影响的规则。三者都保留人工声明语义和有依据的例外；代码与政策冲突并列记录，不能通过删政策使新代码看似合规。sync 复用当前 diff、测试和原正文，在原语义位置直接修订；机械检查不写知识，不发起证据冻结或全仓调查；只有本次真正改变业务结构且尚未授权的决定才合并一次语义确认。
