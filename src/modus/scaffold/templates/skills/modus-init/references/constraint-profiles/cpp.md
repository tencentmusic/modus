# C++ 约束调查

以下是取证维度，不是 Team Standard 的固定 H2 模板；最终章节按项目真实机制组织。

先读[共享方法](../constraint-extraction.md)。从 CMake/Bazel target、编译命令、工具链与启用宏确定当前变体，再读方法体和生命周期；不能把某一平台编译图当成全部运行形态。

## 1. 架构/分层/链路事实

- **证据入口与追查**：CMakeLists/presets/toolchain、Bazel BUILD/MODULE/WORKSPACE、公共头文件、target 链接、main/服务注册、RPC/HTTP handler、消息回调与事件循环；追对象创建、接口/虚函数的实际实现、插件工厂、线程入口、资源写入和退出析构。可用 compile_commands 和编译语义提供变体线索，缺失时直接读构建文件与源码。
- **可沉淀与误判**：可执行程序/库职责、公共接口与实现边界、同步/回调交接、线程归属和写入所有者。include 不等于运行调用，链接不等于全部符号被使用；宏未展开、动态装载或虚调用不确定时保留条件及未解析关系。

## 2. 架构约束

- **证据入口与追查**：target 的 PUBLIC/PRIVATE/INTERFACE 或 visibility、导出头文件与符号、安装/发布规则、ABI 声明/检查、Proto/FFI 边界、编译标准/异常/RTTI/布局相关选项；检查跨库传递对象的分配与释放、异常穿越、所有权与线程亲和性，确认宏是否改变公开类型布局。
- **可沉淀与误判**：真实依赖可见性、公开接口兼容条件、跨边界资源释放和线程约束；将强制构建机制与团队惯例分开。私有链接不能直接证明业务禁止跨库调用，源码兼容也不证明二进制兼容；不能从智能指针类型独立推断线程安全。

## 3. 服务治理

- **证据入口与追查**：RPC channel/stub 工厂、deadline/取消/重试、连接/线程池、事件循环、队列容量及拒绝策略；追异步 lambda 捕获、回调取消、对象销毁、stop/join/shutdown 的先后关系。核对 gRPC/brpc 等实际配置与启动注册、指标/日志及监控配置。
- **可沉淀与误判**：共享客户端、延迟预算、生存期、并发/背压、线程切换与退出规则，指出谁持有并释放回调依赖。超时发生不证明回调不会再到达，设置取消不证明业务副作用撤销；成员默认值不冒充部署值，有监控库不等于告警已配置。

## 4. 中间件知识

- **证据入口与追查**：数据库 session/事务 RAII 封装、prepared statement、返回状态及 commit/rollback、线程/连接绑定；查 DDL、租户/状态条件、索引和批量上限。沿 Redis/消息客户端 wrapper 查 key/TTL 单位、buffer/view 生命周期、确认/重投和序列化兼容；查配置 reload、任务调度、搜索和对象存储封装。
- **可沉淀与误判**：团队采用的资源获取/归还、事务作用域、错误处理、消息幂等和数据兼容条件。RAII 存在不等于资源实际已被正确移交，析构清理不等于业务事务提交；锁仅保护某临界区，不证明数据库或跨进程的原子性。

## 5. 代码规范约束

- **证据入口与追查**：公共 Status/Result/异常、unique_ptr/shared_ptr/raw pointer/span/string_view 的接口约定、复制/移动和自定义 deleter、锁封装与获取顺序、clang-format/clang-tidy、GoogleTest/Catch2/fake；核对回调捕获 this/引用是否超过对象生命周期以及错误是否被丢弃。
- **可沉淀与误判**：错误协议、所有权/借用、异步捕获、锁和线程约束、命名与测试默认方式，附公共类型及实际调用者。不能见到 raw pointer 就写全项目禁止裸指针，也不能因 shared_ptr 自动释放就声称并发访问安全；旧代码的裸 new 或未检查状态不构成推荐。

## 6. 工程规范

- **证据入口与追查**：工具链、C++ standard、编译器/标准库、Conan/vcpkg/Bazel 依赖锁、特性宏和平台矩阵、生成头文件/Proto；查实际 CI 的 configure/build/CTest、ASan/TSan/UBSan、静态检查、打包和兼容验证。区分 Debug/Release、测试配置和生产 target。
- **可沉淀与误判**：受支持变体、公共编译选项的传播条件、依赖/生成器版本、验证命令与 ABI 变更检查。构建命令、sanitizer 或静态检查未执行需如实说明；单一变体通过不代表全部平台通过，不执行未核验的项目构建脚本来“证明规范”。

## 组合查证示例

若服务异步回调借用请求 buffer：追 buffer 分配 → 捕获/提交 → 完成或超时 → 销毁与线程切换，并核对测试是否覆盖晚到回调。项目可记录共享所有权协议，具体模块记录请求取消与资源释放时序；未知回调保证列待确认，不能凭析构函数推断安全。

机制核验参考：[CMake 构建规格与依赖传播](https://cmake.org/cmake/help/latest/manual/cmake-buildsystem.7.html)。目标项目版本、宏和工具链决定实际成立范围。
