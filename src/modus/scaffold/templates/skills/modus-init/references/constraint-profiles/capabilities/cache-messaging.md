# 缓存与消息

按实际使用分别选题；以下为通用建议。沿公共封装、配置、生产者/消费者与反例确认范围，未激活依赖不能证明适用。

## 缓存

默认复用 key builder、序列化、TTL 单位及失效入口。说明权威来源、用户/租户隔离、空值和查询失败区别、写后失效顺序；客户端 query cache、本地持久缓存与服务端 Redis 不能共享未经核实的生命周期。锁需独立核对持有者、租期、释放和失败，不能仅凭缓存封装推断。

检查切换身份、陈旧读、缓存不可用、并发回填、失效失败及重启；单模块 TTL 只落该范围，不写全项目常量。

## 消息

默认复用已有发布/消费、错误和重试机制，明确受理、持久写入、提交、ack/offset 各自含义。核对幂等键、重复/乱序、毒消息和部分批成功；不能把 broker 重投称为业务幂等，把 DB 回滚称为消息撤销。

需要跨资源一致性时先查真实 outbox/任务记录及恢复者；没有实现时记录缺口，不用模式名补造保证。验证提交前后失败、重放、停机与确认点推进，具体协议由产品适配或项目证据补齐。
