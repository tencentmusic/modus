# 公共编码基础

适用所有语言；以下默认是通用建议，只有经目标项目证据核验才可写成归纳约定或明确要求。语法、命名、格式与资源机制由所选语言及实际工具配置细化。

## 值、集合与转换

从请求/类型/校验器、工具函数、转换器及调用者核对：缺失、null、空白、零和失败是否不同？集合是否允许 null 元素、重复、乱序或修改？ID、时间、金额的单位与精度是否一致？

| 场景 | 默认做法与复用 | 改用条件与检查 |
| --- | --- | --- |
| 字符串/空值/比较 | 优先已核实工具或语言标准库；校验后比较；明确 blank 与 empty、值与引用、大小写和数值语义 | 签名/密码不随意 trim 或忽略大小写；测缺失、空白、零、精度与不同类型 |
| 去重、分组、索引 | 分别选择集合、一对多映射、唯一映射；明确顺序和重复策略，复用现有业务键构造 | 允许重复才归并；唯一数据冲突应显式失败，不默认最后覆盖；测重复键、空元素和顺序 |
| DTO/对象转换 | 先找现有 converter/schema/生成源；显式表达字段、单位、空值与敏感字段裁剪 | 只为真实映射复杂度采用框架；不凭字段同名批量复制；测单位、缺失字段、旧协议兼容与输入未被修改 |
| 批量处理 | 先找批接口；校验整批或报告逐项结果，限制单批和在途量 | 不能 filter 掉非法项后返回全部成功；失败不等于空列表；测部分失败和重试范围 |

## 复用导航

调查公共工具、客户端、服务、组件、包、错误码、请求基类和线程池，输出本项目“场景 → 准确入口 → 契约 → 代表调用 → 不适用条件”。不用全仓符号清单替代选择依据。新封装前先检索同业务能力，追到实现或可信版本文档；`safe`、`common`、`async` 等名称不证明保障。

只有稳定共同规则或真实变化点才抽象；相似几行可以留在各自业务。不要为每个类建接口、为一次字段转换加映射依赖、为少量条件构建策略引擎。选中的示例不得绕过现有装配或公共错误模型。

## 方法、条件、格式与注释

默认阅读顺序是校验、加载、判断、执行、转换结果；授权过滤按实际契约在读取/写入处落实。提前结束无效分支，复杂条件按业务含义命名，保留短路和副作用顺序；不为减少嵌套提前访问可空值。纯转换可以用语言惯用表达，外部调用、状态修改和分支错误处理宜显式展开。

圈复杂度、方法行数、参数数目等阈值先查启用的 lint/analyzer/CI 和团队声明。无依据时建议按业务动作拆分、隔离副作用、用具名条件和覆盖分支；不发明“最多十行/复杂度必须小于某值”。简单表达保持连续，复杂构造按语义展开；以目标项目格式器和同范围约定为准，不传播参考项目的空格、换行、注入或注释偏好。

注释解释原因、单位、兼容、失败和所有权；名称与签名能表达的内容不逐行复述。约定若覆盖类/方法/字段，也检查配套示例和生成模板；局部任务不扩成全库格式重写。

## 错误与资源

区分成功无数据、业务拒绝、依赖失败、部分成功与取消。沿项目错误类型/状态码传播，在能解释的边界转换并保留原因；完整日志由能承担处理责任的一层记录，带必要关联信息并脱敏。通用 catch 返回空值不能作为容错模板。

创建者、使用者与关闭者要明确；复用共享 client/pool 时调用方不关闭，局部资源用语言提供的确定性清理机制。异常、提前返回、超时和取消都检查释放路径。并发、DB、配置等复杂行为继续读取专项，不在这里复制实现。
