# 选择、组合与扩展

## 按运行边界选择

规范支持与解析能力分别维护。复用语言注册、构建单元和 Surface 画像提供的候选，但不修改解析注册来宣称规范覆盖，也不因 parser 缺失跳过项目材料。按“服务/包/构建单元 → 实际运行边界 → 源码路径 → 当前任务”收窄：

1. 从 K1 的团队材料、用户明确偏好、工具配置、锁文件、target/source set、启动与装配形成候选。记录语言版本、目标平台、来源及未决项；文件扩展名、依赖存在和少量相似写法不足以激活模块。
2. K2 在原执行卡正文记录 `范围/路径 | 版本与环境 | 候选模块/锚点 | 选择依据 | 待核验 | 编码场景与主落点`。这是可恢复的选择记录，不是新 schema。可由团队或用户指定模块；指定表达要求，不能证明代码已采用该机制。
3. K3 用装配和实际调用验证候选，记录选用、排除或待确认及原因。定义、代表使用者、旁路、工具生效情况互相核对。未证实适用的模块只保留调查问题，不把其实现写成默认方案。
4. K5 只读取选中模块的相关主题；公共基础读一次，专项定义一次，适配器补差异。对同一规则合并前先比较条件、性质、来源和版本；相同语义共用主定义，不将各模块正文顺序拼接。
5. 产物入口按任务提供“场景 → 适用路径/平台 → 默认复用入口 → 规则/示例/例外”的导航。编码消费从这一导航选择，随后核验当前源码签名；缺口按准确主题续读，不先扩大检索数量或全量读取。

同语言不同环境分行：浏览器 TS、Node Worker、SSR 的状态与资源责任不同；共享包只取其承诺平台都能满足的约束，平台专用实现放在适配边界。Kotlin commonMain 不可因 JVM 消费者存在而引用 Java API。多语言服务通过真实协议共享契约，不共享语言写法。

例如 Java 后端的批量 DB 任务可组合 Java + backend/worker + concurrency/database/configuration，只有真实装配 Spring/MyBatis/Apollo 时才加对应适配。数据库规则不需要复制到每个语言文件中。Kotlin Android 本地存储也可选 database，但不因此选 backend 或 MySQL。

## 处理性质和冲突

六个维度是内容职责，不是权威排序。每条区分源码事实、明确约束、归纳约定、通用建议、待确认；示例是这些规则的表达方式，不是第六种权威。

| 冲突 | 处理 |
| --- | --- |
| 项目约定与通用默认不同 | 在适用范围内采用有来源的项目细化，保留必要行为边界；不能用通用偏好替换团队排版/注入方式 |
| API/语法与版本或平台不兼容 | 先排除不可用实现，选兼容方案；若政策要求不可用能力，记录矛盾，不能伪造兼容 API |
| 团队政策与源码/工具配置不同 | 并列记录“要求”和“现状/生效范围”；不以代码频率投票、不删除政策、不自动禁用工具 |
| 两份同范围同级材料互相矛盾 | 找时间、来源、替代声明与例外；无解释则保留待确认，影响编码方向才集中澄清 |
| 历史代码不安全 | 可作为反例；安全替代标为通用建议或有依据的约定，不能宣称项目已实现保障 |

运行版本限制可用方案，不能被目录深度或加载顺序覆盖。域不变量、模块专属条件仍分别有主定义。冲突未解时可继续不依赖它的工作，不能用“已合并规范”掩盖未知。

## 模块的内容深度

简单规则用短句加正例即可。复杂场景交代适用条件/版本、证据入口和调查问题，再回答“什么时候用 → 默认复用谁 → 怎么写 → 关键边界 → 何时换方案 → 如何检查”。准确入口包括包/导出名或配置身份、签名、空值、单位、异常、副作用和所有权。没核实的符号标为示意，不能作为可复制的项目 API。

示例与所选规则一同审核：依赖/版本/前提、格式/注释、错误、资源、平台、并发和工具配置不能相互矛盾。复制参考项目只能借内容深度与表达，不带入业务标识、账号、固定容量或团队偏好。

## 未适配与扩展

未适配技术使用公共基础、已确认的工程类型和专项问题，联读[通用取证](../../../using-modus/references/authoring/evidence/language-adapters/generic.md)，再查目标版本官方材料与当前源码。明确“尚无该语言/框架专用默认写法；已核实哪些调用与哪些边界未验证”。不把通用降级标为全面支持，也不强造新依赖或包装层。

新增模块的最小工作：

- 在[索引](index.md)登记稳定入口、选择条件与覆盖限制；语言入口独立，专题可从入口继续分拆，共享部分通过链接复用。
- 补版本/平台、生效证据、默认方案、复用和例外；适配器只写与公共/专项规则的差异及组合边界。
- 贯通 K1 候选、K2 场景、K3 核验、K5 输出和消费导航；使用原执行卡，不新增并行状态机。
- 用独立编码任务检查真实入口、行为、失败边界与无关依赖；保留负例（版本不匹配、依赖未激活、同语言不同环境、冲突）。调优样稿与验证输入分开，结构/链接检查只验分发，不给内容质量打分。

内置指南升级只更新技能资源；项目规范保持人工所有。稳定入口及可选专题的发布边界见[Team Standard 合同](../../../using-modus/references/authoring/framework/deliverables/team-standard.md)。
