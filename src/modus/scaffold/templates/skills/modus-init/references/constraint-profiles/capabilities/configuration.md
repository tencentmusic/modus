# 配置：类型、覆盖与生效

适用实际配置读取或本次新增配置；所有工程类型均可选。通用建议：沿“声明 → 解析/绑定 → 校验 → 覆盖 → 读取者 → 生效/恢复”调查，复用真实配置门面，不在各调用点重复解析 env/JSON/表达式。配置中心有依赖但无启用/监听不算动态配置。

默认把多个关联值绑定为一个有类型、可校验的快照；默认值只在契约允许时使用，缺失必需值应报错。明确数字单位、边界、空集合、关闭/无限等特殊值；不要把 `0`、false、空串混同缺失。示例必须使用当前绑定器支持的泛型、转义和默认语法。

List/Map/嵌套 Map 先找已有绑定方式及合法样本，核对重复 key、空元素、分隔符、空白、类型转换失败和默认值。简单标量沿既有机制；复杂配置若表达式难以阅读/校验，优先项目已有类型绑定或 JSON 门面，不能为建议擅自引入新库。

覆盖关系从代码与部署材料查出，不能预设 env 永远覆盖文件。分别注明构建时、启动时、请求时、动态更新；setter/注解存在不证明消费者重新读取。动态更新默认先完整解析和校验再发布不可变快照；非法更新沿已实现策略保留旧值或拒绝，不能声称未实现的原子刷新。一次操作需要一致值时只捕获一次快照。

检查缺失、非法值、边界、覆盖优先级、并发读更新和回滚；确认日志不输出秘密。配置变更涉及池、连接、缓存或任务时另读对应专项，字段更新不等于资源已重建。本项目生产值不可得时只写代码默认、键和未知范围。
