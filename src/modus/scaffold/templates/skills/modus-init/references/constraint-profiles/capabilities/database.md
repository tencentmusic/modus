# 数据库：查询、写入与迁移

适用实际访问关系库或本地 SQL 存储的服务、客户端、CLI、Worker；没有数据库装配时不选择。默认是通用建议。先读驱动/ORM 版本、连接/事务工厂、查询源、DDL/迁移、代表调用及 raw SQL 旁路；框架和方言差异交给适配器。

## 默认写法与复用

| 场景 | 默认方案 | 关键边界与换方案条件 | 检查 |
| --- | --- | --- | --- |
| 列表/分页 | 复用现有 repository/DAO 与参数化查询；筛选、授权、排序、count 同口径 | 排序不唯一补唯一键；深分页/持续扫描按既有游标协议；空权限/空 IN 不能退成无条件查询 | 同值排序跨页、无权限、空集合、过滤一致；快照/并发插入要求另核验 |
| 条件更新 | 在同一 SQL 中限定归属、ID、预期状态/版本；核对影响行数 | 零行按已有结果模型区分冲突/不存在/幂等，不能一律成功；需多条原子操作才开事务 | 两个竞争更新最多一个获胜，重复调用结果明确 |
| 事务 | 复用真实事务入口和同一连接/句柄，缩短持有时间 | 跨资源副作用不随 DB 回滚；事务中发消息需真实一致性方案，不能只写“使用 outbox” | 异常回滚、连接旁路、提交失败、提交后通知失败 |
| 建表/迁移 | 沿现有迁移源和命名；明确键、唯一性、NULL、单位、时间语义与真实查询索引 | 审计字段/软删值不是跨项目通用模板；大表/在线变更按实际版本与流程 | 新旧代码兼容、存量回填、默认值、约束冲突及回滚可行性 |

先确认已有批接口，避免循环 N+1；参数化不能替代对动态表名/排序字段的白名单。不要照抄参考项目的表名、状态值、字段长度、时区或存储引擎。

## 有前提的 SQL 示例

通用建议的结构示例；只有目标项目已存在 `work_item(tenant_id,id,status,version)` 且驱动使用命名绑定时才可改写使用，下列标识不是项目 API。复用 DAO 执行，不能自行另开连接绕过事务：

```sql
UPDATE work_item
SET status = :next_status, version = version + 1
WHERE tenant_id = :tenant_id AND id = :id
  AND status = :expected_status AND version = :expected_version;
```

由可信入口提供租户，业务校验允许的状态转换，再检查影响行数。SQLite/MySQL/PostgreSQL 的参数占位、返回值、锁与迁移语法依实际驱动细化；此例不证明授权、重试或跨库原子性已经实现。
