# HTTP 与文件处理

两个主题独立选择，只读当前任务相关部分。以下为通用建议；从实际客户端/文件封装、创建者、调用者和关闭路径取证，版本与平台决定可用 API。

## HTTP

默认复用已装配 client、认证、序列化和错误映射，核实连接/请求超时、重试与取消。先检查状态与协议再转换数据；类型声明不代替运行时验证，失败不变空成功。读取响应体要释放/消费资源，流式响应、上传、下载另核对大小和生命周期。

仅幂等或有真实去重保障的操作重试，沿总预算核对 SDK/代理/业务层叠加。浏览器取消不能证明服务端撤销写入。验证失败状态、非法响应、旧结果晚到、超时、取消、重试副作用与身份隔离。

## 文件

默认复用文件/对象存储门面；核实路径归属、编码、大小、流式处理和关闭者。临时文件在成功和失败分支清理；用户文件不因错误自动删除。需原子可见时先核验同文件系统替换语义及并发版本保护，不能把单文件 rename 称为多文件事务。

上传/解压/导出核对真实边界：路径穿越、符号链接、容量与部分产物。验证中断、磁盘满、编码错误、重复目标、并发修改和失败后的可恢复结果。CLI 与桌面本地文件也适用，不绑定后端对象存储产品。
