# N4 能力模型

本层回答：已解析的证据支持哪些从入口到效果的行为？

| 可以做 | 不得做 |
| --- | --- |
| 以公开触发器为起点，按预算遍历带类型边，在明确效果处停止，保留循环、截断与解析状态，选择代表路径 | 调用 LLM、把每次库调用当作效果、穿越未闭合的运行时边界或决定最终领域 |

公开生命周期动词：`compose`。

框架入口观察与边界解析属于 N2；N4 消费它们经过 N3 解析后的契约。

消费侧只按已确认的 declaration correspondence 归组同一声明的结构/编译观察，原记录不改写。不同构建上下文、重载冲突和未确认对应仍保持歧义。入口信号需要运行源码中的可执行声明；类、模块等容器不能直接成为执行种子。归组同时用于信号归属和路径端点，避免入口能够命名却无法接入调用链。

所有有效种子保留 `seedInventory`，深度展开仍受切片与遍历预算限制。N5/N6 将入口摘要及未展开原因投影到对应 `sourceEntry.capabilitySeed`；查询只读取已发布结果，不重新组合能力。
