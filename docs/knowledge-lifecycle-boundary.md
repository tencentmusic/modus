# 知识生命周期与边界

本文规定从仓库事实到长期知识的跨层契约：N1–N6 产生有界、经过身份核验且可复现的证据；K1–K6 拥有业务判断、事实闭环、正文表达与发布。机器产物是证据，不能直接成为已创作事实；作者也不能宣称机器层未建立的完整性。

跨层生命周期以本文为准；K 侧细则见[创作契约](authoring-contract.md)，安装后的 `references/authoring/**` 是其按需加载的运行版本。这样保持 N6 → K1 的交接可审查，同时避免复制整套正文规则。

-->

## 端到端流程

```text
源码 + 配置 + 模式 + 工具链
    ↓ freeze
N1 源码基线
    ↓ observe
N2 程序事实
    ↓ resolve
N3 关系解析
    ↓ compose
N4 能力模型
    ↓ project
N5 创作投影
    ↓ package
N6 创作上下文包
────────────── 机器与创作的边界 ──────────────
K1 完整范围 → K2 全局主定义与跨域依赖
    → 当前 Domain：K2 细化 → K3 ↔ K4（逐工作单元）
    → 下一 Domain：K2 → K3 ↔ K4
    → K5 项目约束 → K6 系统概览与发布
    ↓
可持续维护的中文开源知识树
```

| 边界 | 拥有 | 不得宣称 |
| --- | --- | --- |
| N1–N6 | 冻结输入、观察事实、解析关系、能力切片、创作投影、经过认证的上下文 | 最终业务范围、正文质量或发布就绪 |
| K1–K6 | 范围决策、主定义、证据闭环、读者表达、系统组装、CAS 发布 | 无法追溯到源码、机器产物或用户明确材料的证据 |

机器产物只通过经过身份核验的 N6 上下文和精确展开句柄交接。范围工作从 `scope-discovery` 开始；K3 仅在候选、边界、路径或符号范围的证据能改变当前结论时继续获取。建议、代表路径、覆盖回执和候选边是导航线索。缺失或争议证据回到窄范围 N6 查询或当前源码，不触发无界重扫或自动范围决定。

<!--
机器层保持输入身份与证据精度；预算和缺口是输出契约的一部分。
-->

## 第一部分：机器层 N1–N6

每个分析产物绑定同一基线，可复现、可核验、可丢弃。机器生命周期在 N6 结束；源码评审、业务判断、用户确认与知识正文属于 K 侧。

| 层 | 问题 | 产物 | 公开动词 |
| --- | --- | --- | --- |
| N1 | 本轮准确输入与环境是什么 | `CorpusBaseline` | `freeze` |
| N2 | 冻结输入中直接观察到什么 | `ObservedFacts`、`SourceEvidence` | `observe` |
| N3 | 哪些身份和带类型关系可安全绑定 | `ResolvedProgram` | `resolve` |
| N4 | 证据支持哪些有界入口到效果行为 | `CapabilityModel` | `compose` |
| N5 | 哪些创作建议由能力模型支撑 | `ProjectionProducts` | `project` |
| N6 | 当前任务最少需要哪些已认证证据 | `AnalysisBundle`、`EvidencePage`、`AuthoringContextPacket` | `package` |

每个阶段包只导出一个生命周期动词。结果只包含本层产物、`baseline_digest` 与规范回执，不嵌套完整上游结果。

<!--
修改阶段依赖时同步AST架构检查；延迟导入也不能让下游反向拥有上游职责。
-->

### 依赖规则

```text
corpus ← facts ← resolution ← capability ← projection ← packet
```

语义包只导入自身或左侧阶段。`store` 与 `runtime` 不导入任何语义包；管线只拥有锁、资源策略、进度与非语义计时。N1 冻结后，所有源码读取与解析属于 N2。N5 仅消费 N3/N4，不能读取快照、检测入口或调用私有观察器。N6 只能核验、发布、查询、约束预算，不能观察源码或创造语义事实。延迟导入也不能绕过此规则，`tests/machine/test_architecture.py` 从 AST 执行检查。

<!--
新增进度字段只进入观察通道；计时、调度和展示翻译不得参与内容摘要。
-->

### 进度与运行状态

进度属于观察通道，不能改变证据、身份、调度或错误语义。构建命令的 stdout 保留给最终 JSON 回执，中文进度写到 stderr。顶层事件对应六个动词，N6 使用稳定阶段标识：

```text
package.verify-inputs
package.portable.*
package.safety.*
package.catalog.*
package.verify-bundle
package.publish
package.prune
package.complete
```

长循环在已知总量时输出 `progress=<completed>/<total> unit=<kind>`，否则输出递增完成量。常规更新节流，阶段转换与自然结束始终发出。终端只转换展示副本；`timings.packageStages` 单独返回观察计时，不进入内容身份。

同步构建返回前应视为仍在运行，不能仅凭耗时、stdout 安静或 N6 阶段较长判定挂起。只有明确取消或返回失败才结束无回执的构建。原子发布保证中断的临时候选不会成为可消费证据包。

<!--
新增输入种类时同步分类回执与摘要组成；冻结阶段不承担源码语义解释。
-->

### N1：冻结主张边界

发现允许的输入，对路径只分类一次，捕获不可变字节，记录配置与工具链坐标，并计算：

```text
corpusDigest          = 已选择路径 + 来源角色 + 内容摘要
analysisContextDigest = 分析配置 + 已声明外部输入
baselineDigest        = corpusDigest + analysisContextDigest + 契约版本
```

每个路径明确标示纳入、排除、不支持、过大或不可用。N1 不解析声明、不绑定符号、不推断行为。冻结到发布间发生变化时抛出 `DriftError`。

<!--
扩展提供方时同时声明失败策略与覆盖回执；可选缺口和必需失败不可混用。
-->

### N2：独立观察

负责结构提取、编译器观察、入口检测、边界观察与创作规则信号。不可变扩展注册表包含：

- `StructuralExtractor(SourcePath) -> dict[str, Any]`：一份冻结源码。
- `CompilerProvider(paths, config, BuildUnit) -> SemanticFacts`：构建单元语义。
- `EntryDetector(relative, content, language, extraction) -> dict[str, Any]`：直接入口观察。
- `BoundaryResolver(source, facts) -> dict[str, Any]`：源码局部框架边界。

解析器字典留在 N2；跨层使用带类型的 `SourceEvidence`。可选提供方失败形成局部执行状态、完整度、稳定原因码和 `CoverageReceipt`，其他语言继续；配置为必需时抛出 `ProviderError`。

<!--
关系解析必须保留证据来源与歧义状态；稳定排序不能替代绑定依据。
-->

### N3：解析身份与关系

协调带来源的观察，不改写其出处。负责实体身份、类型关系、编译器与语法的上下文对应、未解析结果、拓扑、方法图与视图隔离。

精确、候选、启发式、未解析和拒绝状态保持区分。歧义是数据，不能选择排序后的第一个符号冒充确定关系。无效的可选投影以有界拒绝回执隔离；内部不变量失效抛出 `InvariantError`。

<!--
调整遍历策略时保留硬预算、终止效果及截断信息，身份不依赖执行顺序。
-->

### N4：组合能力

从有证据的公开入口出发，按硬预算遍历 N3 关系，在明确的终止效果处停止：数据写入、状态变化、事件发布、外部调用、文件写入、缓存变更。

`CapabilitySlice` 携带稳定身份、触发、权威对象、终止效果、代表路径、解析度、覆盖、截断与歧义。身份来自语义签名，不取决于行号或遍历顺序。N4 不调用 LLM、不持久化产物、不选择最终领域。

<!--
建议只能引用已有证据；聚合时省略的内容须留下数量、缺口与展开入口。
-->

### N5：投影创作建议

规范输入、选择建议起点、执行有预算的聚合并组装视图。能力优先，结构社区仅为辅助信号，目录或图聚类不能成为已创作事实。

未覆盖证据必须以剩余项、歧义或缺口可见。省略细节有数量统计；可能影响创作决策时，还需精确展开句柄。

### N6：打包、查询与发布

核验基线、构建目录、原子写入、认证根身份、执行有界查询、组装任务上下文。`module-authoring` 保留选中的建议与代表路径，将范围内 `authoringSignal` 附到建议，并提供解析度、来源层、见证、省略与展开句柄。这些信号定位事务、状态、权威写入、资源、消息和入口，不能替代源码评审。

创作上下文 packet、分析包及 select 页各自使用 `schemaVersion: 1`，上下文契约随 CLI 与正文模板同步更新。packet 通过 evidence 保留库存/入口/关系原记录，通过 coverageGaps 传递各次查询缺口，通过 expansionQueries 给出可选的精确展开条件；receipt counts 按最终交付计数，代表路径保留顺序、来源与整条裁剪语义。

创作上下文回显 `bundleDigest`、`baselineDigest` 与精确 `requestedScope`。没有候选、能力、路径或符号选择器的 `module-authoring` 请求必须拒绝。能力句柄可直接传给 `context` 与 `select`。

内部独立处理目录构建、原子发布、打开时认证、完整性检查、游标编码、证据查询与上下文组装。消费者边界只有：

```python
analyze_repository(root, options, *, progress=None) -> AnalysisReceipt
open_analysis(root, AnalysisIdentity(bundle_digest, baseline_digest)) -> AnalysisBundle
query_evidence(bundle, EvidenceQuery(...)) -> EvidencePage
build_authoring_context(bundle, ContextRequest(...)) -> AuthoringContextPacket
```

身份对象防止两个摘要顺序混淆。包契约使用 `baselineDigest`，单文件见证使用 `sourceDigest`。游标绑定已认证证据包与规范查询。仅在省略证据可能改变当前判断时续读，并保持原筛选与准确游标；省略游标或只修改 `maxItems` 都会从第一页重新开始。游标耗尽不是创作完成条件。

### 存储与诊断

证据包使用 `schemaVersion: 1`。页按内容寻址、目录按范围索引、发布原子完成。暴露数据页前先验证声明的根和元数据，不把源码正文复制到包中。未知或历史缓存形态以规范错误码拒绝并重建，不提供旧缓存迁移。

语义摘要排除墙钟计时、工作线程数量、调度顺序、缓存复用、资源配置和宿主绝对路径。相同输入与语义策略在不同执行配置下保持同一身份。

| 硬失败 | 含义 |
| --- | --- |
| `ContractError` | 请求或传输契约无效 |
| `IntegrityError` | 产物被修改或结构损坏 |
| `DriftError` | 冻结输入在使用或发布前变化 |
| `BudgetError` | 预算无效或无法满足 |
| `ConfigurationError` | 注册表或仓库声明无效 |
| `ProviderError` | 必需提供方未满足契约 |
| `InvariantError` | 已验证输入进入不应存在的内部状态 |

硬失败均为 `MachineError`，携带 `machine.<owner>.<kebab-reason>`。持久化诊断只存稳定码、安全摘要、有界数量和脱敏仓库相对坐标，不存异常原文、绝对路径、凭据、身份证件号码或敏感源码字面量。CLI 的 JSON 保留同样的代码与结构化细节，人工阅读模式补充中文恢复建议。

### 扩展与验证

新增语言需在同一可评审变更中声明、注册、证明：在 `language-registry.json` 声明后缀、角色、提取器、能力层级、编译器、边界解析与入口检测；在 `facts/extension_registry.py` 注册名称及版本；提供发现、可选工具降级、入口到效果与上下文输出夹具。动态插件加载不在本契约内。

Go 示例声明 `extract_go`、`go`、`builtin-go-frameworks` 与入口检测器，启动验证名称及 `go-types/1` 实现版本。有工具链夹具验证语义事实，无工具链夹具验证仅 Go 语义覆盖下降，结构和通用文本证据继续可用。

验证包括架构与根导出、注册声明一致性、严格 JSON Schema、行为/漂移/游标/预算/篡改/敏感值、代表语言夹具、严格 mypy（解析器局部边界有明确例外）、Ruff、wheel 内容与独立运行时，以及 `git diff --check`。覆盖率供本地分析，无强制比例门槛。

## 第二部分：创作层 K1–K6

六阶段各自对应[运行入口](../src/modus/scaffold/templates/skills/using-modus/references/authoring/index.md)中的一个 `stages/k*.md` 文件。init/reinit 先确定完整范围及全局主定义/依赖，再逐域推进 K2 → K3 ↔ K4，最后 K5/K6；并非先把全库 K3 做完再批量成稿。阶段没有新增机器状态，现有执行卡继续作为唯一恢复依据。

[上下文合同](../src/modus/scaffold/templates/skills/using-modus/references/authoring/context-continuity.md)规定压缩前检查点及恢复必读；[跨域合同](../src/modus/scaffold/templates/skills/using-modus/references/authoring/cross-domain.md)从 K1/K2 保存主定义和交接，K3/K4 传播变化，K5 提炼工程约束，K6 双向核对并编写概览。并行时使用固定委托合同和可检查的事实输入包，不通过自由重写各域提示词改变质量要求。

创作层在 N6 后开始，在实际知识树完成语义评审、机械完整性与原子写入后结束。N 层提供证据，K 层拥有判断与正文，两者不能互相宣称对方的完整性。

### 契约来源

```text
references/authoring/
├── stages/k*.md          K1～K6 六个编排入口
├── evidence/            上下文包与源码如何成为闭合事实
├── framework/           各知识产品需要向读者表达什么
├── context-continuity.md 压缩前保存与恢复
├── cross-domain.md       跨域事实、依赖与变化传播
└── publication.md        语义评审、机械完整性与安全写入
```

这些 Markdown 是创作规则的源文件。模板目录原样验证与分发，Python 不在安装时注入另一份标题、运行形态或完成规则。

K5 的[编码规范组合](team-standard-composition.md)在既有 constraint-profiles 内组织公共基础、独立语言入口、工程类型、专项和框架差异，再与项目/团队材料组合。解析和 Surface 仅提供候选，实际适用性按路径、版本、运行环境与装配核验。产物提供工程边界、复用导航和有条件的默认写法；稳定入口及可选一级专题共享人工保护和 CAS，指南升级不覆盖项目规范。

证据指南拥有包解释、范围、场景闭环和语言导航；框架拥有产品角色、主定义、读者问题、运行形态、本地化与图表；技能拥有 init/reinit/update/sync 的范围及路由；验证器拥有客观文件、链接、锚点、身份、可移植性和泄漏检查；写入安全拥有哈希、锁、CAS、原子替换、所有权及删除顺序。各边界不能复制或接管其他边界的规则。

四种工作流共用证据、框架与发布契约：init 创作完整首次快照，reinit 重证完整既有快照，update 修改明确局部范围，sync 只修改当前任务造成的最小长期影响。

init/reinit 只通过认证的 `context` 和 `select` 读取机器产物，不能直接解析存储目录、数据页或清单。K1 用 `scope-discovery` / `reinit-diff`（后者交付当前基线，不计算新旧差分）；K2/K6 接入 service-boundary 与双向服务关系，K3 按需使用 constraint-extraction，K5 复用同源规则信号并按公共机制范围补证；每个变化模块获取自身 `module-authoring`；每个领域在读者评审前分别请求各源码范围的 `coverage-audit` 并合并结果，同一轴内取并集、不同轴取交集。不可用则回读当前源码并记录卡内缺口，不借旧包、不发无界模块请求、不用一个领域请求推动多个独立模块。执行卡的 requestedScope 是 Module 知识 ID，packet 的同名字段是实际查询对象；原卡正文按[消费合同](../src/modus/scaffold/templates/skills/using-modus/references/authoring/evidence/machine-packet.md#六阶段消费与可恢复记录)保存映射、来源、事实主落点和缺口处置，K6 做双向对账。生成的 `modus/knowledge/**` 路径不是源码选择器；空、无匹配或部分结果不能直接变成 `reviewed`。

### 完整性与阶段门槛

决策完整表示足以采纳、拒绝、拆分或保留具名歧义；入口完整表示每个入口有所有者、排除理由或缺口；内容完整表示每个采纳事实的字段、分支、完成、失败与恢复已核查。它们不等于翻完证据页、每个声明都有模块或达到字数。

继续 `select` 只为回答：尚未展开的证据是否可能改变范围决策、入口归属或正在撰写的结论？`nextCursor` 只表示可继续读取，不是发布门槛。

| 阶段 | 输入与工作 | 产物与所有者 | 完成与回退 |
| --- | --- | --- | --- |
| K1 范围建模 | N6、源码、材料、既有身份；按结果与归属建模领域、模块、平台、基础设施与排除项 | 已确认范围及入口处置；范围作者负责，用户确认实质结构变化 | 决策与入口覆盖完整；缺口回窄查询或源码 |
| K2 创作计划 | 范围、框架、运行形态、语言适配；记录 ID、真实场景、主定义、证据/图表计划和进度 | 既有执行卡中的逐领域工作单元；主作者协调 | 每个场景和共享事实有唯一去向；范围问题回 K1，证据问题回 K3 |
| K3 证据闭环 | 逐模块选择器上下文；回读关键方法、配置、测试；每个场景只调查一次 | 可复用事实集、明确缺口、`evidence-ready`；领域所有者负责 | 采纳事实内容完整或有诚实缺口；回到能改变结论的窄证据 |
| K4 领域成稿 | 稳定专题、模块、路由，完成覆盖审查与读者评审；脚本只盘点和验证，不模板生成叙事 | 一个完整领域子树；单一所有者创作，主作者验收 | 新人、贡献者、维护者任务通过且主作者回读；正文/证据回 K3，范围回 K1 |
| K5 项目约束 | 复用前序事实与机器线索，核对公共机制、使用者、强制检查和反例，独立创作或保留 Team Standard | 可追溯的工程要求、适用范围与验收结果；主作者负责 | 原始依据支持规则性质；保护人工规范，冲突回 K3/K4 或本阶段 |
| K6 系统概览与发布 | 消费 K4/K5，双向复核交接，编写概览与规范导航，再全局验收、机械核验、回读和清理 | 系统入口、长期知识树与实际交付结果；主作者/写入会话负责 | 共享产物已验收、所有目标有终态、实际检查与发布回读完成；冲突仅回受影响目标 |

K3 沿“触发 → 输入 → 前置条件与决策 → 编排 → 权威写入 → 返回或异步交接 → 可见结果 → 失败与恢复”调查一次，再投影到相关文档，不按输出文件重复扫仓库。

init/reinit 每次进入或恢复领域时，K2–K4 先按[逐域加载与恢复](../src/modus/scaffold/templates/skills/using-modus/references/authoring/evidence/scope-modeling.md#逐域加载与恢复)读取唯一执行卡中的范围、模块归属、selector 和进度，再加载对应证据、相关已有正文与写作规范。上下文压缩后复用同一流程；必要证据已丢失时按原精确范围重新获取，不重跑 N1–N6 构建，不以摘要或状态字段代替取证，也不把这套完整域编排扩展到 update/sync 的局部维护。

### 所有权与执行

每个领域同时只有一个作者，串行足以完成。只有用户明确授权且宿主支持时，工作者才可拥有不重叠的完整领域；不能按文件类型或模块拆给多个正文作者。派发完整范围、逐模块源码选择器和 requestedScope、固定摘要、契约、路径、哈希、受保护内容、图表机制、读者问题、验收与交接格式。主作者先校准一个复杂领域与一个普通/较薄领域，再派发后续批次。

主作者独占执行卡，并保留根概览、团队规范、业务种子、共享词汇、跨域协调与最终发布。工作者只写指定的生成领域子树并返回交接。工作者完成或领域核验 `clean` 不能直接标记 `reviewed`；主作者必须回读实际输出并串行合并状态。回退串行保持相同语义，并行不能成为正确性或 CI 依赖。

稳定身份从 K1 开始：`domain:<slug>`、`module:<domain>/<slug>`。`D2`、`P3` 等序号不是身份，不能进入长期正文。跨领域内容使用中文名称、稳定 slug 与规范路由链接。人工 `constraint` 与 `business` 默认保留，除非用户明确选中维护。

### 排障与变更路由

| 现象 | 阶段 | 修复方向 |
| --- | --- | --- |
| 公开入口无归属或被忽略 | K1 | 入口盘点、排除理由、能力拆分、窄查询 |
| 模块重叠或技术目录成为领域 | K1 | 结果、权威对象、生命周期、变更责任 |
| 同一事实多处定义或接口/对象每符号一页 | K2 | 唯一主定义、入站链接、语义分组 |
| 重复扫描同一链路 | K3 | 场景优先闭环与可复用事实集 |
| select 总返回同一批 | K3 | 保持筛选并使用准确返回游标，改页大小不能续读 |
| 只列方法，无法解释完成与恢复 | K3 | 回读权威写入、测试与完整场景链 |
| 标题齐全但读者问题未回答、正文重复 | K2–K4 | 真实场景盘点、九维语义回读，禁止模板化叙事 |
| 领域页变成方法级源码目录 | K4 | 证据移入模块/专题，领域保留路由 |
| 事件方向或状态归属冲突 | K3/K4/K6 | 跨域协调、唯一图表所有者与统一术语 |
| 图能渲染但边没有证据 | K3/K6 | 核查调用、装配、协议、配置、读写、消息或测试 |
| clean 但正文浅薄 | K3/K4/K5/K6 | 回到相应主定义，按读者任务修订；机械核验不为正文打分 |
| 正文含 D2/P3 等临时序号 | K1/K4/K6 | 改为名称、稳定 slug 与规范链接 |
| 不可读文档、不安全路径、坏链接/锚点、漂移、开放围栏、身份冲突、敏感值 | K6 | 修复客观缺陷并定向复验 |
| 并发修改覆盖了新内容 | K6 | 读取时哈希、CAS 冲突、受影响目标回读 |

仅锚点移动留在 K6，不重新确认范围。实现变化回 K3 并修订原主定义；新公开入口、新能力或实质结构迁移回 K1，复用一次性确认卡。接口/对象布局是 K2/K4 编辑工作，不触发领域/模块确认。只有参与者、方向、归属、状态、条件、完成或恢复语义变化才重画图，行号或模板变化不足以触发。

### 核验边界与发布安全

机械核验只检查无需编辑判断即可确定的事实：知识是受约束的可读常规文件、不经符号链接逃逸；围栏闭合；链接、文件与 Markdown 锚点可达；`anchors.locations` 使用可移植仓库坐标且仍定位到声明源码；无机器绝对路径与高置信度敏感值；可选模块元数据安全可解析且与路径身份一致。

不得强制标题、顺序、H3/分片数量、专题完整度、页顶导航、人工业务种子的字节不变、隐藏覆盖回执、证据预算、图表数量或特定语言措辞。这些属于语义评审或项目编辑选择。

发布核验额外要求 `schemaVersion: 2` 执行卡、逐模块精确证据状态、领域覆盖、已履行图表决策、结构化模块锚点，以及机器拥有的正文中不出现源码路径。`clean` 只表示实际运行的机械检查通过，不证明业务事实、证据闭环、图表选择、可读性或设计质量。

写入安全不因核验范围精简而削弱：完整读取并记录哈希，按文档加锁、CAS 检查、原子替换。迁移先写并回读新主定义，修复入站链接与导航，再以原哈希删除已确认的旧生成文件。人工约束和业务内容保持不变，除非明确获授权。

实际发布核验通过后，回读真实文件，如实报告写入、删除、未变化目标、冲突、跳过与证据缺口，再删除执行卡和空目录。普通核验不能代替发布核验，未运行的检查不能宣称通过。
