# 知识创作契约

本契约规定单仓库知识的证据消费、范围建模、正文、维护、核验与发布。机器提取、检索排序和工作区聚合有各自的实现契约；[生命周期边界](knowledge-lifecycle-boundary.md)连接机器证据 N1–N6 与创作决策 K1–K6。

安装后的[创作参考](../src/modus/scaffold/templates/skills/using-modus/references/authoring/index.md)是本契约供助手按需读取的模块化版本。指南和新创作知识默认使用简体中文，用户明确要求时才切换正文语言。Python 与模式负责稳定协议和写入安全，不注入另一份正文规范。

“必须/不得”保护正确性、协议、所有权与安全；“应当”是可以由项目证据说明例外的默认规则；“可以”允许按复杂度和读者需求选择。示例标题与表格属于编辑指引，除非明确声明为传输契约。

## 规则所有权

| 职责 | 拥有 | 不拥有 |
| --- | --- | --- |
| 证据 | 上下文包解释、源码调查、材料来源、场景闭环 | 文档布局、必需标题、正文长度 |
| 框架 | 产品角色、稳定路径、主定义、读者问题、本地化与图表 | 语言专有扫描、发布写入 |
| 编排 | 工作流选择、阶段转换、恢复与路由 | 证据、正文或验证规则的副本 |
| 核验 | 路径、身份、链接、锚点、围栏、可移植性、泄漏检查 | 语义质量、完整度评分、图表配额 |
| 安全 | 路径约束、人工所有权、锁、读取时哈希、原子写入、顺序删除 | 编辑决策 |
| 邻接系统 | 机器分析、日常检索、工作区导航 | 重新定义长期知识的事实 |
| 测试 | 可观察行为与稳定边界 | 为测试便利发明正文要求 |

发生冲突时按责任解决：证据决定可以主张什么，框架决定放在哪里，六阶段入口决定编排顺序，发布规则决定验收与收尾，安全规则决定能否写入。修复实现不能削弱这些不变量。证据责任或产品语义变化时，同步设计与运行参考；局部编辑选择不能升级为全局规则。

这些约束保护证据、身份和人工所有权，调整时同时检查运行时校验。

## 不变量

1. 安装后的创作指南始终是可直接评审的 Markdown。
2. 机器建议、聚类、覆盖率、名称与推断路径都是线索，不自动成为领域、模块或业务结论。
3. 每个事实只有一个主定义，其他页面摘要并链接。
4. 稳定路径、slug 与身份独立于中文标题。
5. 运行形态、编程语言、正文语言是三个独立维度。
6. 机械核验只报告确定性缺陷，不能证明事实、证据闭环或可读性。
7. 人工所有权、路径约束、CAS、锁、原子替换与安全删除始终有效。
8. 质量由证据与读者评审决定，不能以字数、标题数、图表数或隐藏覆盖标记代替。
9. 每个领域同时只有一个创作所有者。并行是可选方式，需用户明确授权；串行具有相同语义。
10. 主作者拥有共享文档、执行卡、跨领域协调与实际文件的最终验收。

## 生命周期

```text
N6 上下文包 + 当前源码 + 测试 + 配置 + 用户材料
    ↓
K1 完整范围 → K2 全局主定义与跨域依赖
    → 当前 Domain：K2 细化 → K3 ↔ K4（逐工作单元）
    → 下一 Domain：K2 → K3 ↔ K4
    → K5 项目约束 → K6 系统概览与发布
```


运行时路由见[六阶段入口](../src/modus/scaffold/templates/skills/using-modus/references/authoring/index.md)：[开始或恢复](../src/modus/scaffold/templates/skills/using-modus/references/authoring/index.md#开始或恢复)统一判断续作、项目类型和稳定身份，阶段入口定义输入、动作与出口，共享细则维护唯一规则。编号用于导航和恢复，不新增机器状态。init/reinit 共用此路线；update/sync 仅复用受影响的细则。默认串行，委派须有明确授权。

### K1：范围建模

单域任务仍完成 K1～K6，共享规范与概览只处理已授权范围的影响，保留其他域与人工内容；具体执行见 [K1](../src/modus/scaffold/templates/skills/using-modus/references/authoring/stages/k1-scope.md)。

使用本轮经过身份核验的 `scope-discovery` 上下文；重建时使用 `reinit-diff` 获取当前基线证据，再由作者比较旧知识和当前实现；此 intent 不执行新旧差分。通过 `context` 和定向 `select` 消费证据，不把证据包目录或数据文件作为创作协议。机器证据不可用时读取当前源码、测试、配置并记录覆盖缺口，不借用旧包冒充本轮证据，也不把有界查询替换为全仓扫描。

对每项能力确定触发、期望结果、权威对象、写入者、最终可见效果、失败责任与生命周期。模块代表输入、决策、结果与变更责任一致的任务；领域按长期结果、权威对象或变更责任聚合模块。非商业项目的领域可以是能力边界。目录接近、聚类、通用基础设施、框架适配器或 controller/DAO 技术层本身不构成领域。

按[材料覆盖](../src/modus/scaffold/templates/skills/using-modus/references/authoring/evidence/index.md#材料覆盖)逐篇盘点已确认业务域、references、modules、关联知识及用户材料；指定文档集合递归读完范围内子目录/子文档，授权网页系统查阅当前账号在授权范围内可见的功能，记录读取位置、冲突和缺口影响。源码仍按场景定向读取，外部查阅不自动授权业务写操作或保存副本。

每个公开入口族都需归属于正式领域/模块、跨领域平台能力、共享基础设施、有理由的排除项或明确缺口。记录稳定 ID、目标语言名称、结果、入口族、权威对象、运行形态、构建单元、语言、邻接关系和覆盖限制。

| 完整性 | 含义 | 不要求 |
| --- | --- | --- |
| 决策完整 | 足以采纳、拒绝、拆分或保留具名歧义 | 耗尽原始记录 |
| 入口覆盖完整 | 每个公开入口族都有归属或处置 | 读取全部声明 |
| 内容完整 | 已采纳事实的字段、分支、完成与恢复均已核验 | 展开无关证据 |

仅当更多证据可能改变范围、入口归属或当前结论时继续 `select`。非空游标不构成发布失败。省略返回的游标会重读第一页，修改页大小不会续读。

首次完整结构只确认一次；reinit 保留身份，仅确认新增、拆分、合并、迁移、重命名或有证据的退役。符号移动、标题、锚点与专题分片不改变范围。用户已明确授权完整范围时复用该授权。

项目确认时链接完整执行卡，并展示四列表格：领域名称、说明、模块数量、模块名称。仅给数量、slug 或抽样不足。宿主支持且适合委派时，把按领域并行与串行列为独立选择，并提供修订、重新生成选项；确认串行不授权委派。工作区成员确认使用独立流程。

### K2：创作计划

由通用读者问题、模块实际运行形态的并集、语言证据适配与可用仓库证据组成模块契约。混合语言项目按构建单元分别识别。

共享事实规划唯一去向：接口在 `api.md`，对象在 `object.md`，规则在 `rule.md`，生命周期在 `state_machine.md`，协作在 `downstream.md`，资源在 `infrastructure.md`。模块拥有完整场景叙述并链接共享定义。临时归属图写入执行卡，不新增长期知识产品。

只保留一份 `scope-confirmation.md` 执行卡；单仓直接记录 Domain 计划，工作区在根卡中按已配置成员 ID/path 隔离同构的 Domain 计划，成员核验从工作区根传入 `--publication --member <member-id>`，不复制分仓卡。按[机器消费合同](../src/modus/scaffold/templates/skills/using-modus/references/authoring/evidence/machine-packet.md#六阶段消费与可恢复记录)区分 Module 知识身份与实际机器 requestedScope，建立查询 → 记录/源码 → 已核验事实 → 正文主定义的映射，保留相关反证、限制、缺口和省略处置。保存本轮摘要或机器不可用原因、入口处置、稳定 ID、各模块选择器、精确请求范围、证据模式与缺口、以源码为范围的领域覆盖审查、主定义、图表决策、读取时哈希、计划写入/删除与进度。状态字段遵守[运行时范围契约](../src/modus/scaffold/templates/skills/using-modus/references/authoring/evidence/scope-modeling.md)。

状态只能根据实际证据与评审推进。工作者完成或核验 `clean` 不能直接把领域标记为 `reviewed`；主作者必须回读实际文件并验收覆盖审查。只有主作者写执行卡。续作时在领域边界保存状态，丢失原卡后不得根据已有输出重建一个缩小且全部已评审的卡。

首次调查、恢复和局部维护共用[定位、读取与复用](../src/modus/scaffold/templates/skills/using-modus/references/authoring/evidence/index.md#定位读取与复用)：从真实路径和当前命令帮助取证，按缺失范围有界读取，分别处理无匹配、执行失败和输出截断。读取结果及有效版本沿用已有会话或初始化原卡记录，不建立另一份状态。

init/reinit 在进入领域或中断恢复时，按[上下文合同](../src/modus/scaffold/templates/skills/using-modus/references/authoring/context-continuity.md)依次读取原卡、对应证据、相关正文和适用规范。每个可恢复单元原位保存关键条件、来源、跨域边界、文件版本与验收债务；未知写入先核对实际文件。容量不足缩小工作单元，不能缩减范围、重跑 build 或凭摘要续写。

K2 必须为全范围先建立[跨域协作基线](../src/modus/scaffold/templates/skills/using-modus/references/authoring/cross-domain.md)：提供方/使用方、主定义、字段/状态映射、术语、交接前已提交事实、完成与恢复责任、双向依据及受影响页。先稳定依赖契约，循环依赖由根作者联合取证；K3/K4 发现变化立即传播并重验受影响页，不能等 K6 才拼接。基线标识与变化记录放原卡正文，不扩机器 schema。

K2 提前确认实际预览环境，最终分别报告机械核验、语义回读、整页与逐图结果；具体边界见[发布合同](../src/modus/scaffold/templates/skills/using-modus/references/authoring/publication.md)。

现在规划图表候选与合理豁免，在 K3 揭示当前工作单元的实际机制后、相应正文生成前确定本单元的图形安排；随后续单元继续完善同一领域计划。记录问题、图表类型、唯一所有者、证据与引用页面。导航表不能代替异步交接、持久状态、多条件决策、对象映射或资源生命周期的机制说明。

写前在执行卡已有正文中安排每篇要回答的读者问题、事实主落点、叙述顺序，以及正文、步骤、表格、图和贯穿案例各自承担的解释任务。按[编辑规则](../src/modus/scaffold/templates/skills/using-modus/references/authoring/framework/editorial.md)组织表达，按需选择[对照样稿](../src/modus/scaffold/templates/skills/using-modus/references/authoring/framework/examples.md)校准；样稿不提供当前项目事实，也不要求复制其标题或篇幅。K3 补齐事实后原位调整安排，不新增卡片、schema、状态或平行验收 receipt。

[初始化质量要求](../src/modus/scaffold/templates/skills/using-modus/references/authoring/framework/index.md#初始化质量要求)及用户明确的篇目、案例和最低图表要求记录在卡片已有正文与适用的 `visuals` 中，优先于通用的按需选图建议；不能用 `waived` 自动豁免用户要求。[执行策略](../src/modus/scaffold/templates/skills/using-modus/references/authoring/execution-strategy.md)只调整调查、撰写和回读的组织方式，不因模型、上下文或工具差异降低本契约。

恢复与复用由[上下文合同](../src/modus/scaffold/templates/skills/using-modus/references/authoring/context-continuity.md)统一定义：上下文丢失或交接后实际读卡并恢复；同一作者仍持有完整有效证据时定向补读，工具错误本身不要求重载。未知写入和 CAS 冲突仍核对实际结果，不以连接存续推定模型持有证据。reinit 未授权补建缺失 Team Standard 时，以明确保持缺失并说明影响作为合规处置，不伪称已创作、不阻止其他已授权目标收尾。

### K3：按场景闭合证据

每个模块使用自身候选、能力、源码路径或符号选择器请求 `module-authoring`。核对两个摘要、请求范围、覆盖、省略项与展开句柄。领域级选择器不能为多个独立模块闭环。仅在触发、结果、完成与恢复所有者都一致的不可分割场景中共用请求，并记录原因。

每个场景只调查一次，再将事实投影到各自的主文档：

```text
触发 → 输入 → 前置条件与决策 → 编排 → 权威写入或产物
     → 返回或异步交接 → 最终可见结果 → 残留影响与恢复
```

上下文包定位关键方法体、注册、配置、SQL、资源处理和测试，不能代替回读。闭合公开契约、不同输入输出行为、关键字段、对象、规则、状态、恢复、协作与资源边界，不能按每份输出文档重复扫描同一场景。

按[事实投影路线](../src/modus/scaffold/templates/skills/using-modus/references/authoring/evidence/scenario-closure.md#从机器线索到正文主定义)消费入口、对象、效果、资源、关系与限制。不同 intent 的同源信号可能嵌入候选或分布在多个顶层数组，不能只读 `evidence` 或候选名；信号所在位置不赋予权威性或终态保证。机器没有交付的字段、默认、权限、配置生效与恢复条件要定向补证，缺信号不表示无能力。原卡连接来源、已核验条件、主定义和场景/案例/图的使用处，保留尚未写入的事实。

区分当前实现、明确需求、已核验设计意图、标明的推断与确实不可得的证据。未调查的事实不能写成不可得，更不能成为结论。每条图表边都需调用、装配、协议、配置、数据访问、消息、测试或明确材料支撑；静态可能性不等于必然运行路径。

用已闭合的输入、分支、数据变化、结果与失败恢复充实正文和案例。示意数据须明确标注，不能为增加篇幅补造业务背景、规则、权限或恢复保证；案例暴露的事实缺口仍在本阶段定向补查。

在执行卡已有场景记录中，将入口族展开为逐接口清单，将范围内对象展开为完整字段集合，关联各自的详情落点、共享定义或具名缺口。声明、注册、序列化与实现共同确定集合，不能从已经写好的小节反推覆盖。继承、嵌套、枚举和响应包装均需可定位；动态或不可得边界具体说明。基础定义覆盖每个成员，关键成员继续追查行为。兼容回退、否定布尔、优先级与部分成功按“条件 → 选值/分支 → 副作用 → 返回/完成”记录，供跨页核验复用。

领域验收前，分别使用已确认**源码**请求执行 `coverage-audit` 并合并结果；不同 selector 轴在一次请求中取交集，不把它们当作 OR。生成知识路径和执行卡不是源码选择器。空、部分或未匹配结果需回读源码或明确记录缺口，不能宣称完整覆盖。

### K4：完成一个领域

先稳定当前工作单元涉及的专题定义，随即写对应模块场景、案例与图并交叉回读，再推进下一单元；不要求先完成全域六专题再写模块。全部单元完成后补齐专题总览与领域路由，逐篇全量验收。写作暴露缺口就回到证据。一次完成一个连贯领域批次，不先为全部领域铺设浅层骨架。

init/reinit 按[初始化质量要求](../src/modus/scaffold/templates/skills/using-modus/references/authoring/framework/index.md#初始化质量要求)全面覆盖目标，逐篇兑现案例、图形与实际预览。没有证据时保留具体缺口；机械检查器不按图数评判语义质量，局部 update/sync 不因此扩大范围。

默认交付详实的开发与排障手册：每完成一个契约组、对象或场景就逐项对账并编辑回读，再推进本域下一组。先写完整条件、因果、处理、结果与正常/适用失败案例，再安排导航、段落、步骤和分组表格；篇幅随业务复杂度增长，不以简短为由漏项。宽表拆分且保留稳定字段标识，长解释进入相邻正文，避免整页列表或一格塞入完整流程。

长页按业务语义组织字段组和接口组，保留逐项详情、组间解释和直达条目的导航。长标识保持可复制的原始拼写；挤占表宽时调整签名、类型和长解释的承载位置，不在标识中插入空格/断字符，不靠强制逐字换行、缩小字体或只加宽临时预览解决。API/Object 分片仍保留根入口并按语义分组，不按单个方法或 DTO 分文件。

写前逐模块、逐核心场景完成选图判断。复杂交接、返回后继续执行用时序图，条件路径和副作用顺序用流程图，精确条件比较可用表格。图前说明问题，图后解释完成与失败；已有领域导航表或不同问题的专题图不能豁免本场景。额外场景的简单关系或同一问题已由主图解释时给出具体理由，不能豁免初始化/用户配图要求，也不能靠机械图数决定质量。

领域作者逐篇完整回读本轮目标正文，包括六专题及其分片、全部目标模块和领域路由。先核对业务事实与覆盖，再按编辑规则检查行文、表格、图文配合与案例，修复后回读受影响内容。评审应确认：新人能解释真实任务，贡献者能找到修改与验证入口，维护者能识别权威状态、残留影响与恢复责任。检查受理与完成、公开契约覆盖、共享事实归属和邻接边界，再运行领域机械核验。

按[逐篇验收与事实对账](../src/modus/scaffold/templates/skills/using-modus/references/authoring/publication.md#逐篇验收与事实对账)在原卡中逐页记录读取范围、清单对账、跨页事实核对、编辑与预览结论、剩余动作。接口和字段主定义必须实际包含所引条目；API、Object、规则、模块、图和案例中的同一条件与结果须一致，冲突回源码裁决。不能用“全部回读”或文件数量代替验收；缺项、待修事实冲突和已知阅读缺陷未解决时不推进 `reviewed`。后续编辑使旧验收失效时，仅重开受影响 Domain/Module 的既有 `authored` 状态并复查；证据失效先补证。预览工具不可用可以明确保留限制，但不能把未预览写成通过。

首个有图页面成稿后即确认已有工具能实际渲染图形；打开请求已排队、HTML 加载或图源着色都不能作为通过。逐图分别记录事实一致性、渲染和页面阅读结果，`authored` 只表示内容落地。目标阅读器不可用时可使用权限允许的已有替代工具，明确环境和宿主未验证范围；不能因无渲染能力豁免必需图。

本轮新写或实质修订的页面在实际使用的阅读环境中从页首连续查看到页尾，覆盖长表各组、所有图与前后说明、内部导航落点；长截图缩小后无法辨字时分段查看。记录验收版本、已看与未看章节、逐图结果，首屏抽查、无横向溢出和截图存在不代表整页可读。发现问题后修订实际 Markdown 并重新查看受影响页面；预览不可用时保留具体待验位置，不能以 Markdown 回读或机械 `clean` 宣称实际预览通过。

获授权的工作者拥有一个领域的全部专题、模块、图表与路由。写入范围不包括其他领域、源码、人工业务知识、约束、根概览或执行卡。派发完整的逐模块选择器、固定摘要、契约、目标路径、哈希、受保护内容与读者问题。工作者返回证据、改动、冲突、图表、覆盖、验证与跨域交接；主作者回读并串行协调，工作者不能代替完整系统验收自身产物。

主作者的代表性抽查是对领域作者全量逐篇验收的二次校准，不能替代前者。宿主支持且当前授权允许时，可使用隔离上下文的独立读者只凭正文完成读者任务，并返回无法回答或容易误解的位置；否则由当前作者转换读者视角回读，如实区分自查与独立读者反馈。此增强不产生新的正文所有者或执行状态，也不改变默认委派规则。

并行委托使用[固定合同](../src/modus/scaffold/templates/skills/using-modus/references/authoring/domain-worker-prompt.md)，只填事实输入，不逐域重写验收指令。原卡保存输入包、实际发送文本与共享基线，worker 必须读取相同 K2/K3/K4 及适用细则；根作者核对 handoff 所用基线和实际文件，变化时重验相关页。首波通过后再派后续，换作者前确认前任停止写入。

### K5：提炼项目约束

根作者独立负责 Team Standard 的取证、创作与验收。输入沿用 K1 的技术栈/材料/保护范围、K2 的主定义计划、K3 的公共机制与反例，以及 K4 最终领域/模块。K4 正文帮助定位使用者和业务差异，规则的成立仍回到原始源码、配置、测试、CI 或明确材料；多个页面重复引用同一机制不会增强证据强度。

首次 init 仅在 Team Standard 缺失或精确匹配当前框架种子时填充，reinit 默认不补建或刷新。通过 `knowledge update` 显式选择 `initializeTeamStandard`，锁内复查种子与读时哈希；明确委托的人工维护使用独立的 `allowTeamStandard`，二者互斥。已有人工规范从 K1 起读取并遵守，不能等 K5 才发现政策。

复用本轮 `constraint-extraction` 证据，按“机制 → 使用者 → 强制检查 → 旁路/反例”补齐共享工程路径。命名、职责、注释、错误传播、恢复、扩展、兼容和一致性按真实机制组织；逐条说明性质、范围、触发、要求、依据、例外、失败影响和验证。领域不变量及模块专属限制仍在各自主定义。用具体改动回读规则能否指导实施，核对 K4 的实际边界；冲突回所属 K3/K4，不把现状自动提升为政策。向 K6 交付实际规范版本、适用性、必要摘要和具名偏差。

### K6：系统概览与发布

先双向复核跨域交接：用机器 serviceRelation 与当前源码反查提供方和使用方最终文件，检查双方共同遗漏。统一事实所有者、发送/接收方、受理/完成信号、权威/派生状态及术语；事实冲突回 K3/K4，规范性质或范围问题回 K5。

随后消费 K4 与 K5 最终产物编写根概览：项目目的、角色、能力地图、运行单元、跨领域关系、导航和贡献/验证入口。规范只保留入口和理解系统所必需的摘要，完整依据、例外与验证留在 Team Standard。根概览解释系统关系，不能拼接模块摘要或复制规则全文；reinit 只修订受影响事实。新增域的缺失 business 索引及结构迁移在本阶段完成，人工正文仍受保护。

语义评审、机械完整性与写入安全是独立门槛。核验实际树、修复问题、按读取时哈希发布并回读。迁移先建立并评审新定义，修复入站链接与导航，再以原哈希 CAS 删除旧生成文件。人工链接仅在明确授权范围内修改。

隐藏来源元数据后，按目标读者检查正文：

- 能否理解谁在什么条件下做什么、得到什么结果；
- 能否区分正常流程、失败、例外和恢复方式；
- 必要的技术标识是否解释清楚，并保留准确拼写；
- 表述简化后，是否仍保留影响行为的关键条件；
- 段落、步骤、表格与图是否各有用途，读者能否顺畅定位并理解完整过程；
- 图是否回答明确问题，图中条件、方向与完成信号是否和相邻文字一致。

这些问题适用于所有运行形态，是语义回读责任，不转化为固定标题、术语词表、中文正则或机械评分。

全局阶段检查跨领域归属、导航、引用、术语、完成口径和发布完整性；代表性抽查用于校准质量，不能弥补任何目标正文尚未逐篇回读。编辑和预览发现的问题沿用执行卡正文的结果、缺口与下一动作保存，不另建评分或完成状态。

所有已确认目标均 `reviewed`，具有 `changed` 或 `unchanged` 终态，共享文档完成、发布检查通过且最终文件回读后，还须核对原卡中本轮约定的整页/逐图验收没有待修或待验项，才删除执行卡；仅清理空目录。工具不可用、预览部分完成或用户将效果留待另行试用时，可以交付正文并说明边界，但保留原卡与待验位置，不把语义 reviewed 或机械 clean 当作视觉通过。分别报告写入、删除、未变更、冲突、跳过、机械结果、内容回读、整页预览覆盖、逐图结果和剩余缺口，不为同一工具限制反复请求批准。

反馈范围保持精确：边界变化回 K1，证据缺口回 K3，跨领域冲突回所属 K3/K4，链接或 CAS 冲突只回到受影响目标。

六个专题入口文件保持稳定。大型接口/对象专题可按语义分片，保留概览与链接；不能每个方法、端点或 DTO 一页，也不在每个专题复制模块清单。

模块回应九类问题：`boundary`、`scenario`、`data-state`、`public-entry`、`collaboration`、`runtime`、`constraint`、`recovery`、`implementation`。它们是评审维度，不是九个必需标题。默认按边界、真实场景、实现/扩展/验证组织，按需展开。非平凡场景必须解释不同字段、决策、写入、完成、失败、恢复和验证；表格与方法名不足以闭环。

来源追溯复用 frontmatter 中的现有元数据；代表性文件使用 `anchors.paths`，源码位置使用 `anchors.locations`，包括支撑术语解释的定义、注释与行为位置，不虚构符号或行号。生成正文不得放完整源码路径、行号、`path#L` 引用或证据目录。根与领域路由保持稳定导航。隐藏 frontmatter 后，因果叙述仍须可读；元数据不能成为隐藏证据倾倒区。

### 术语解释、行为表达与来源追溯

所有运行形态共用以下规则，安装后的详细表达约定见[本地化与术语解释](../src/modus/scaffold/templates/skills/using-modus/references/authoring/framework/localization.md#术语解释行为表达与来源追溯)：

| 规则 | 要求 |
| --- | --- |
| 优先使用有证据的业务名称 | 业务缩写、内部代号、历史名称、状态码与枚举值依据项目注释、定义或文档解释，不凭拼写猜测。 |
| 区分自然叙述与精确标识 | 已有目标语言定义的状态/枚举在业务叙述中使用该名称，独立页面或场景首次出现附原码；精确接口、字段、配置、命令与代码示例保留原始拼写和真实协议值。 |
| 解释行为，不只转述代码 | 方法说明用途，布尔值说明控制什么，状态说明进入与退出条件，返回值说明是否代表最终完成。 |
| 保留条件、例外与不确定性 | 无可靠含义时保留原词；同名异义按范围解释；材料冲突说明差异，不在简化时抹去影响行为的条件。 |
| 来源放入现有元数据 | 记录支撑解释的代表性文件或源码位置，正文保持连贯；不新增来源协议或强制术语清单。 |

`qm/kg/kw` 只是一类缩写示例，不形成专用映射或验收词表。这些规则不要求所有专业术语翻译成中文，也不因目标语言变化而改写技术标识。

目标为简体中文时，对已有中文含义的术语按[应用规则](../src/modus/scaffold/templates/skills/using-modus/references/authoring/framework/localization.md#已定义中文含义的应用)区分类型/字段、枚举成员、实际传输值与显示名称，核对构造绑定、注释、字典或国际化映射及当前使用。机器包缺少释义时定向回定义补证；不将符号保真扩大成自然叙述只能保留英文。映射在对象/状态专题定义一次，模块、规则、案例、图中可见标签和本轮获授权的说明性注释复用中文名称；不得只在字典完成解释。跨页回读从映射反查使用处，遗漏属于内容修复；JSON、SQL、命令、代码和原始引用中的真实值保持不变，不做全局字符串替换或增加中文正则门禁。含义不明或存在冲突时记录范围与差异，不凭英文拼写补造名称。

## 适配与图表

规范运行形态为 `backend`、`frontend`、`cli`、`library`、`worker`、`data`、`infrastructure`、`plugin`；未确立形态时用 `generic` 中立问题。混合形态合并关注点，不拼接多个标题模板；编程语言或框架名不是运行形态。

| 形态 | 重点 |
| --- | --- |
| 后端 | 授权、事务、权威存储、同步/异步边界 |
| 前端 | 用户动作、路由、表单与状态、请求、可见反馈、取消 |
| CLI | 参数/环境、进程与文件效果、输出流、中断、退出码、清理 |
| 类库 | 宿主责任、公开 API、所有权、资源、异常、并发、兼容 |
| 工作进程 | 选择、租约、执行、确认、提交、重试/死信、停止 |
| 数据 | 来源、转换、质量、分区、检查点、水位、落点、重放 |
| 基础设施 | 声明、依赖、计划/应用、状态、漂移、回滚、销毁、保护资源 |
| 插件 | 发现、注册、能力协商、宿主调用、隔离、禁用、卸载 |

[语言适配器](../src/modus/scaffold/templates/skills/using-modus/references/authoring/evidence/language-adapters/index.md)按构建单元回答八类证据问题：构建图、公开入口、类型/序列化、控制流与效果、并发/事务/资源、配置、验证工具链、解析器/编译器降级。核验代理事务、协程取消、浏览器/服务端边界、所有权/析构或状态后端等实际机制。适配器不能引入语言专有的知识目录或标题。

本轮目标语言统一传递到正文创作、图表与回读；中文专属用词规则只在目标为中文时适用，不新增语言配置或审批。正文、标题、表格与图表标签默认简体中文；用户明确指定其他语言时一致切换。不能随源码注释、材料或会话语言自动改变默认。路径、slug、协议字段、命令和源码标识保持原样；语言变化不改变身份与事实归属。reinit 在已确认范围内统一语言，局部维护不扩大写入授权。

用正文解释原因与例外，用表格表达精确映射，用图解释难以线性阅读的机制。多参与方、受理/完成分离、持久状态、重试补偿、有序决策、跨领域交接、权威/投影差异或资源依赖都应评估图表；没有用户或专用交付要求的额外场景，简单同步操作无需为配额画图。init/reinit 每份状态、协作和模块文档按专用要求选择有依据的最小有用表达；没有持久状态可以解释真实阶段流程，不能伪造状态。模块可以用场景投影说明当前任务，完整机制主图仍只有一个主落点，不复制完整主图。

| 问题 | 表达方式 | 配套说明 |
| --- | --- | --- |
| 职责与归属 | 架构/上下文图 | 所有者与边界 |
| 交互顺序 | 时序图 | 完成、失败归属、超时 |
| 有序决策 | 流程图 | 真实条件、优先级、例外 |
| 持久生命周期 | 状态图 | 完整转换表、守卫、效果、恢复 |
| 对象关系 | ER/关系图 | 基数、真值来源、写入者、删除影响 |
| 数据转换 | 数据流/血缘图 | 模式映射、检查点、质量边界 |
| 资源依赖 | 依赖/生命周期图 | 配置、状态、回滚、销毁 |
| 配置覆盖或规则组合 | 优先使用表格 | 单位、默认值、优先级、短路 |

每张图回答一个问题，方向、参与者、归属、边界和完成信号都经核验。正文解释范围、证据、省略项、残留效果与自动/人工恢复；图渲染失败时文本仍可用，但不因此视为图表验收通过。导航图不能代替机制图，状态图不能代替时序图。

优先使用 Mermaid 流程、时序、状态与 ER 图；仅当公开类型层级或多态扩展本身是主题时使用类图。条件具体，分支并发真实，边界对应进程、事务、领域或宿主。图标签不放源码坐标与候选 ID；解析或渲染成功不证明边正确。

不能仅凭 ORM 注解推断业务关系、SDK 重试推断幂等、声明推断部署、构建依赖推断运行调用。提交、消息送达、消费、下游完成、权威提交与投影可见可能是不同时间点。关键交接须说明当前可见结果、已提交内容、下一完成信号和恢复；远端结果未知不等于允许重放。

## 工作流差异

| 工作流 | 范围 | 发布行为 |
| --- | --- | --- |
| `/modus-init` | 首次完整项目；可恢复稳定身份则进入重建 | 本轮构建一次证据，补缺失种子，完成领域与概览 |
| `/modus-reinit` | 完整既有快照，保留稳定身份 | 重证事实、跳过相同字节、原位修订，仅确认真实结构变化 |
| `/modus-update-knowledge` | 明确材料/事实及真实受影响的知识 | 不构建初始化证据包，联动主定义、消费者与相关导航 |
| `modus-sync-knowledge` | 当前代码任务的影响调查与受影响场景内的已证实错漏 | 影响未明继续定向取证，确认后最小原位修订；证实无需写入才静默结束 |

init/reinit 先恢复未完成任务，新任务共用本轮只读盘点。根配置声明 workspace 时进入外层导览流程；普通项目根据稳定身份能否恢复选择初始化或重建，部分正文缺失不重建已有身份。入口切换和工作区路由复用盘点，不重复执行 status。

reinit 依次比较身份、入口/对象归属、语义、结构、文件。锚点移动不改变范围。复用准确且可读的正文与图表；参与者、方向、归属、状态、条件、完成或恢复变化时更新图的内容，实际预览发现裁切、拥挤等阅读缺陷时定向修复表达，行号或纯编辑偏好不触发重画。符号消失、部分覆盖或工具缺口不能证明退役。

sync 从当前任务的实际编辑和差异判断影响，包含新增、删除、移动及本轮已提交的修改，不接管已有脏修改或其他作者的变化。只读任务不因此授权写入；格式或测试等调整确认无长期事实影响后跳过。已有正文未提及、找不到知识落点、候选为空或检查器返回 `noop` 都不能作为无影响依据，未明影响需定向调查。最小修订限制写入量，不限制必要取证；受影响场景内已证实的历史错漏一并修复，不扩成无关历史清理或全域复核。

既有模块内的事实、关联、案例和锚点自动维护，按责任与业务结果复用稳定身份；文件移动或新增平台实现不自动构成模块拆分。真实新增、拆并、迁移或退役沿用已有授权，未获授权时在当前任务中合并确认受影响归属、理由与消费者/导航，确认后继续，不要求用户另跑维护命令，也不要求初始化执行卡或全项目结构表。不向主定义追加按日期分隔的变更章节。

update/sync 的编排主定义是[增量维护流程](../src/modus/scaffold/templates/skills/using-modus/references/authoring/incremental.md)。从实际入口、注册、调用者及关键判定核对主定义与真实消费者；共享能力追查受影响业务入口，跨端或多实现按实际装配补证，初始状态、分支两侧、完成和恢复分别核验。沿会改变结论的关系扩展，未变化契约足以解释无影响时停止，不固定全仓扫描或按跳数截断。工程机制变化同时核对 Team Standard 的适用性；没有明确维护授权时保留规范并说明偏差，不自动启用首次填充或维护权限。新增已确认 Domain 复用业务种子服务补齐缺失索引。

局部维护复用编辑和回读规则，只处理受影响页面及关联上下文；从变化/源码到正文、从正文到事实双向对账，对变化的图表或版式做实际预览。不新建执行卡、清单、回执、队列或持久状态，不构建或读取初始化 bundle，也不增加宿主专用步骤。必要上下文随当前会话或已有摘要交接，恢复时核对当前源码与实际写入。落盘回读后按受影响 Domain 运行普通 verify；根概览、跨域迁移或共享导航变化需要普通全局核验，不使用 `--publication`。

结束结论区分无需写入、同步完成与仍未完成。影响已核对且正文准确、没有未解决项时可静默跳写；完成必须覆盖受影响变化及其知识落点或有依据的排除，关联一致、写入已回读且必要核验完成。能在当前任务解决的缺口、输入错误或逐文件冲突继续处理，保留已成功写入；只有确需用户决定、外部信息或工具恢复时才报告具体限制、代码与知识各自的状态及下一动作。机械 clean 不证明语义完整，未验证项不能归为无影响。本流程不承诺发现从未触及的历史盲区或脱离会话上下文自动恢复。

校验、阈值或优先级变化时，逐条重算受影响的已有正反例首先命中的分支，修正失效的失败原因；同一场景的步骤、表格和流程图须保持前置条件与顺序一致。可运行的关键例子用当前实现复核，不能以新增规则段落或机械核验通过代替这一步。

## 核验、安全与演进

验证器检查可读且受约束的文件、围栏、本地链接与锚点、可移植源码坐标、声明身份一致性和高置信度敏感字面量。发布模式另查版本化执行卡、逐模块证据、领域覆盖、已声明图表承诺与结构化模块锚点。不得强制固定标题、措辞、章节数、图表配额或人工种子的永久字节相同。

修改前完整读取并记录哈希；锁定目标，以 CAS 拒绝并发变化，再在同目录原子替换。无变化则跳过。人工业务与约束默认保留。冲突后只回读受影响内容，不得仅刷新哈希后盲目覆盖。迁移先建立新目标与链接，再以原哈希删除旧生成文件。

知识更新请求的写入和删除路径仅限项目根相对的 `modus/knowledge/` 下 Markdown。普通 `README.md`、`evidence.md`、源码和测试按任务授权单独编辑，不混入知识 CAS 请求。非法路径或请求形状在首个写入前拒绝整批请求；合法请求中的逐文件冲突则保留其他已完成的写入。

扩展优先修改既有规则所有者。新语言适配需改变证据导航或降级行为，新运行形态需表达既有形态无法描述的运行责任，新产品需有独立读者任务和唯一事实归属。必要时规定稳定身份、链接、迁移与退役。

旧知识按身份和事实归属读取，不要求匹配当前标题模板。缺失元数据可从规范路径推断，声明冲突必须报告。定向迁移保留有效语义与人工内容，检索兼容不应冻结编辑选择。

契约变化同步设计、运行参考、实现与相关测试。完成要求事实一致、相关证据闭环、归属稳定、正文有用、机械完整、安全发布和诚实报告；格式或产出数量不能替代这些条件。
