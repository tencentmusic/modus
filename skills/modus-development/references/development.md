# Modus 开发流程

目标：把用户需求落到正确所有者，用有意义的检查证明具体行为，并保护原有工作。

## 定位一个改动

先使用只读诊断检查 checkout 和已有修改，再读取当前 `AGENTS.md`（如果存在）、`CONTRIBUTING.md`、模块 README。验证时调用当前 checkout 的 CLI，避免将 PATH 中其他安装版本的行为当作当前实现。

用一句话描述可观察结果，例如“普通 status 在解析器不可导入时仍可用”“旧查询游标不能跨证据包使用”“更新受管文件保留用户编辑”。据此选择所有者和对应测试。只做与这个结果有关的改动。

追一条真实路径：**入口 → 参数/配置 → 核心决策 → 权威写入或产物 → 返回/完成 → 失败与恢复**。读取关键方法体、注册、配置和测试，不根据函数签名推断行为。

| 改动类型 | 必须同时核对 |
| --- | --- |
| CLI 参数或命令 | `cli.py` 注册、`cli_commands/`、`command_reference.py`、中英文 README、真实帮助/退出码 |
| 新内置工作流 | `surface.py`、模板 catalog、宿主调用维度、发布合同、安装/更新/卸载 |
| 模板语义 | `docs/authoring-contract.md` 与随包运行参考的主定义；链接、CLI 示例、安装产物 |
| 语言/观察器 | 声明、不可变注册表、版本/实现指纹、构建单元、缺工具降级、入口到效果夹具 |
| 机器协议 | Python 请求/结果、JSON Schema、摘要组成、查询/游标、错误码、公共导出 |
| 存储或写入 | 所有权、路径、读时哈希、锁、原子替换、并发和失败后的原状态 |
| 检索 | 查询范围、共享预算、语义条目完整交付、部分结果、敏感内容脱敏 |
| 多仓 | 显式 workspace 配置、成员只读、外层写入范围、总预算及不可用成员 |

## 项目实现约束

- 扩展现有职责所有者；CLI 不吞应用逻辑，报告不写文件，语义阶段不跨层补造事实。
- 中文帮助与说明放在展示/模板边界。保持命令、字段、枚举和错误码原样；不用全局 Click/Typer 猴子补丁。
- `networkx`、解析器与分析管线只在分析入口加载。普通帮助、状态、接入及 Markdown/源码检索保持隔离。
- 可选能力缺失报告自己的覆盖缺口。损坏、基线漂移、非法协议或必需能力失败不能包装为空结果或成功。
- 观察器变化可能改变缓存身份；核对 `machine/implementation.py`、`facts/extraction_cache.py`、`store/fingerprint.py`，不能只哈希用户源码。
- 新协议和副作用需要可说明的类型与失败语义；不为减少行数、预想扩展或统一形式引入新层。

## 验证与交付

迭代时跑最小相关测试；行为修复覆盖触发问题和文件保留/失败边界。模板或纯文档变化优先验证链接、真实 CLI 示例和模板目录，不写镜像实现的文本断言。

提交前按当前贡献要求运行完整检查；命令和测试选择见 [验证与发布](modules/quality-release.md)。若未提交代码，只说明本次实际验证，不暗示已通过 CI 或已发布。

验证后检查本轮 diff 是否改变长期职责、场景、契约、对象、规则、状态、依赖、资源或锚点。只修改已存在、确实受影响且在授权范围内的项目知识/文档；只读或无影响任务静默结束。仓库没接入知识时不自动 `modus init`。

完成说明包括行为变化、关键文件、实际测试结果、未验证项。提交或推送沿用用户授权，精确 stage 本次路径并检查 staged diff；skill 创建不意味着交付源码。

## 调用示例

```text
使用 $modus-development，修复普通 CLI 启动加载 machine 依赖的问题，保持现有公开命令和退出码。
使用 $modus-development，新增一种语言的结构观察，先核对 N2 注册和缓存身份，再覆盖缺工具降级。
使用 $modus-development，评审知识更新的并发行为，检查 CAS、部分失败与人工内容保留。
```
